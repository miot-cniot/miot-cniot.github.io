    7. Autorización y autenticación de dispositivos IoT

    Al conectar dispositivos a IoT Core, la autenticación y la autorización desempeñan diferentes funciones en la seguridad de los dispositivos. Como se comentó anteriormente, hay dos áreas donde se debe aplicar la seguridad en los sistemas IoT:

    • Certificados y políticas de AWS IoT. Utilizados para dispositivos y objetos y las aplicaciones que se comunican con ellos

    • Roles y políticas de IAM. Utilizados tanto para operadores humanos como para actores software que necesiten interactuar con el sistema IoT o entre sí

    Una visión general de cómo los dispositivos se conectan de forma segura a AWS IoT Core y de cómo AWS IoT Core interactúa con otros servicios.

    Autenticación de dispositivos

    La autenticación es el punto de entrada a AWS IoT Core para los dispositivos. La autenticación es el proceso de verificación de la identidad de un cliente o de un servidor:

    • Autenticación del servidor es el proceso por el cual los dispositivos u otros clientes se aseguran de que se están comunicando con un endpoint real de AWS IoT.

    • Autenticación del cliente es el proceso por el cual los dispositivos se autentican con AWS IoT Core.

    Como se comentó anteriormente, los dispositivos y los objetos, y las aplicaciones que se comunican con ellos, deben autenticarse y deben ser autorizados para realizar sus funciones (como enviar y recibir mensajes). Los servidores que gestionan la comunicación y los mensajes, como pasarelas y brokers, también deben ser autenticados y autorizados.

    En el proceso de conexión de dispositivos, como el sensor de temperatura en nuestro escenario, AWS IoT Core crea las credenciales de seguridad requeridas para el dispositivo, que consisten en lo siguiente:

    • El certificado X.509, que se utiliza para la autenticación del dispositivo.

    • La política de AWS IoT, que se asocia al certificado y se usa para la autorización del dispositivo, otorgando los permisos necesarios para que el dispositivo realice su trabajo.

    Certificados X.509

    AWS IoT Core utiliza certificados X.509 para conceder acceso al servicio a los dispositivos. Después de que los dispositivos hayan sido autenticados, sus operaciones y acciones permitidas en AWS IoT Core se basan en una política de AWS IoT. Las operaciones incluyen conectarse al agente de mensajes, enviar y recibir mensajes, y obtener o actualizar la sombra de dispositivo de un objeto.

    Normalmente, los dispositivos de AWS IoT utilizan certificados X.509 para realizar autenticación mutua con AWS IoT. Puede registrarse un certificado existente o dejar que sea AWS IoT quien genere y registre un nuevo certificado para el dispositivo.

    AWS IoT proporciona autenticación ofreciendo las siguientes opciones:

    • Certificados para autenticación mutua mediante MQTT sobre Transport Layer Security (TLS) v1.2

    • Solicitudes firmadas por Signature Version 4 (SigV4) sobre HTTP

    • MQTT sobre WebSocket, que es similar a otros servicios de AWS

    También se pueden usar tokens de autenticación personalizados proporcionados por un servicio de autenticación o autorización externo. AWS IoT también ofrece opciones de autorización flexibles y control de acceso granular a través de políticas JSON (JavaScript Object Notation).

    Para obtener más información sobre el uso de certificados para la autenticación, consulta Certificados de cliente X.509.

    Usar certificados de una CA propia

    Además de la forma estándar de usar los certificados proporcionados por AWS IoT Core, los clientes pueden proporcionar su propia autoridad de certificación (CA).

    Una CA es una entidad de confianza que emite certificados SSL (Secure Sockets Layer). Estos certificados digitales son archivos de datos utilizados para vincular criptográficamente una entidad con una clave pública.

    Un cliente puede usar su propia CA si desea un mayor control sobre la validez del certificado y la capacidad de añadir identificadores al certificado. Este enfoque suele tomarse cuando el cliente tiene certificados de cliente firmados por otras autoridades de certificación raíz o intermedias. Este enfoque maximiza la integración con otros proveedores en lugar de usar exclusivamente el AWS Certificate Manager, que es el servicio detrás de la creación de los certificados que proporciona AWS IoT Core.

    Autorización de dispositivos

    La autorización es el proceso de concesión de permisos a una identidad autenticada. Después de que las identidades sean autenticadas, aún no tienen permisos para acceder a los recursos. Para que los dispositivos y los usuarios obtengan permisos, deben ser autorizados para hacerlo. Esto se logra mediante el uso de políticas de AWS IoT.

    Políticas de AWS IoT

    Dispositivos, aplicaciones móviles, aplicaciones web y aplicaciones de escritorio utilizan todas una identidad autenticada. La identidad solo puede ejecutar operaciones de AWS IoT si tiene una política que le conceda permiso. Las políticas de AWS IoT se asocian a certificados X.509. La política define lo que una identidad autenticada puede hacer y concede los permisos necesarios para que el dispositivo realice su trabajo.

    Las políticas de AWS IoT controlan principalmente el acceso de un recurso al plano de datos de AWS IoT Core. Cuando se envían datos a AWS IoT Core y se reciben datos de él, se está usando el plano de datos de AWS IoT Core. Esto significa que el plano de datos define si está permitido conectarse al agente de mensajes, enviar o recibir mensajes MQTT, o publicar-suscribirse a un tema específico.

    En una sección posterior del tutorial se explorarán las políticas de AWS IoT con más detalle.

    Autorizadores personalizados

    Cuando los métodos de autenticación de AWS IoT Core no son suficientes, los clientes pueden usar AWS IoT Core para definir autorizadores personalizados que gestionen la autenticación y autorización. Esto es útil cuando se necesitan mecanismos de autenticación distintos de los que AWS IoT Core soporta de forma nativa.

    Por ejemplo, si se están migrando dispositivos ya desplegados sobre el terreno a AWS IoT Core y estos dispositivos utilizan un token de portador (bearer token) personalizado o un nombre de usuario y contraseña MQTT para autenticarse, pueden migrarse a AWS IoT Core sin tener que aprovisionar nuevas identidades para ellos. Otra razón por la que un cliente podría usar este método sería si el hardware del dispositivo no pudiera almacenar los certificados X.509 o no pudiera almacenarlos de forma segura.

    Cada autorizador contiene una referencia a una función Lambda gestionada por el cliente, una clave pública opcional para validar las credenciales del dispositivo e información de configuración adicional.

    IAM

    Además de la autenticación y autorización de dispositivos gestionadas por AWS IoT Core, los roles de IAM trabajan con políticas de IAM para conceder a AWS IoT Core permisos para acceder al resto de AWS.

    Los usuarios (tanto operadores humanos como actores software) necesitan interactuar con el sistema IoT o entre sí. En este caso, la autenticación y la autorización se proporcionan mediante políticas de IAM que conceden a una identidad de IAM, o recurso de AWS, permisos para acceder a un servicio o realizar una función con AWS.

    Los roles y políticas de IAM permiten que AWS IoT acceda a otros recursos de AWS en tu cuenta en tu representación. Por ejemplo, si quieres que un dispositivo publique su estado en una tabla de Amazon DynamoDB, los roles de IAM permiten que AWS IoT interactúe con DynamoDB.

    Los actores software (aplicaciones móviles, web o de escritorio) pueden autenticarse con servicios de AWS IoT, a través de usuarios, grupos y roles de IAM e identidades de Amazon Cognito. Las aplicaciones web y de escritorio utilizan identidades de IAM o federadas.

    Una visión general de los tres tipos principales de identidad compatibles con AWS IoT para la autenticación y autorización de dispositivos o clientes.

    Roles y políticas de IAM

    Los roles de IAM trabajan con políticas de IAM para conceder a AWS IoT Core permisos para acceder al resto de AWS. Las políticas de IAM conceden a una identidad de IAM, o recurso de AWS, permisos para acceder a un servicio o realizar una función con AWS.

    Por ejemplo, AWS IoT recibe datos y comunicación de un dispositivo que se redirige a un recurso de AWS como un bucket de Amazon S3 (Simple Storage Service), una tabla de DynamoDB o cualquier servicio de AWS.
