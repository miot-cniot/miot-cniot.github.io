    6. Introducción a las reglas IoT

    El problema de la acumulación de datos

    Acumular cada bit de datos de un sensor significa que tendrás una gran cantidad de datos recibidos. Imagina nuestro escenario con nuestra flota de camiones de helados con 10 camiones, cada uno con cinco sensores. Si cada sensor publica, por ejemplo, tres tipos de datos (marca temporal, temperatura o estado de la puerta y estado del sensor) cada 15 segundos, esto representa 60 mediciones cada minuto para cada camión, es decir, 600 mediciones cada minuto.

    La minería de datos de estos datos mediante los servicios de análisis de AWS puede proporcionar información sobre el funcionamiento de la flota. Estos servicios ayudan en la supervisión operativa, que es más una opción reactiva, atrasada en el tiempo.

    Pero para una operación diaria, con una supervisión casi en tiempo real, puede haber elementos específicos de los que se quiera estar al tanto a medida que suceden, para mitigar una situación o tomar una decisión empresarial adecuada apoyada por los datos.

    Imagina una caída súbita de la temperatura en el congelador de un camión. Tener una notificación directa de este evento específico sería útil para el conductor. Sin embargo, la revisión de los datos agregados almacenados en el DataWarehouse de la compañía solo mostraría, p.ej., la temperatura media mensual, lo que no sería útil cuando un camión sufre una caída de temperatura repentina.

    Antes de explicar cómo se solucionaría esta situación, vamos a ver mediante un ejemplo el problema de la acumulación de datos por suscripción.

    Introducción a las reglas

    ¿Cómo gestionar este diluvio de datos para recibir o aislar solo aquellos que nos interesan? Es posible que quieras gestionar de alguna manera la gran cantidad de datos recibidos que no son útiles para tus objetivos comerciales diarios. Algunos datos son necesarios en el momento y otros podrían precisarse más tarde para realizar un análisis a largo plazo. Lo que buscas es una forma de gestionar la gran cantidad de datos recogidos y filtrar o dirigir los datos a diferentes destinos en la nube.

    La gestión de los datos IoT comienza con la aplicación de reglas de AWS IoT. Estas reglas son uno de los principales métodos para filtrar y dirigir la comunicación desde AWS IoT Core a otros servicios de AWS.

    Al usar reglas, tus dispositivos pueden interactuar con los servicios de AWS. Cuando los datos entran en AWS IoT Core, las reglas son evaluadas y las acciones aplicadas sobre los flujos de datos de los temas MQTT. Puedes usar reglas para realizar diferentes tareas, como las siguientes:

    • Escribir datos de un dispositivo en una tabla de Amazon DynamoDB.
    • Invocar una función de AWS Lambda para extraer o transformar datos específicos.
    • Guardar un archivo o un conjunto de datos en Amazon S3.

    Nota

    Para que AWS IoT pueda realizar estas acciones, debes concederle el rol y los permisos de AWS Identity and Access Management (IAM) adecuados para que pueda actuar en tu nombre.

    Anatomía de una regla

    Las reglas tienen como mínimo lo siguiente:

    • Un nombre
    • Una declaración de consulta
    • Una o más acciones a realizar

    También puedes tener información adicional, como la siguiente:

    • Una descripción
    • Una acción que se realiza en caso de error
    • Etiquetas

    Lenguaje de consulta

    Las declaraciones de consulta de las reglas de AWS IoT están escritas con una sintaxis similar al lenguaje de consulta estructurada (SQL) utilizado en el mundo de las bases de datos. La consola de AWS IoT presenta un entorno de desarrollo estructurado para crear declaraciones de consulta para filtrar y enrutar mensajes MQTT.

    La consulta de regla que se muestra en el siguiente ejemplo está seleccionando todos los mensajes enviados por todos los sensores de la carga principal en el camión_1 que informen una temperatura (informada como temp) superior a 37. Esta consulta actúa como un filtro para ignorar los mensajes que no coincidan con los criterios.

    Es posible asociar varias acciones a una única regla. En ese caso, los mismos mensajes filtrados por la regla se envían a varios destinos.

    Reducción de los costes de mensajería

    Cuando hay que enviar mensajes a gran escala, en el orden de decenas de miles o más en un corto período de tiempo, se puede usar la función de ingestión básica (Basic Ingest) para reducir los costes de mensajería.

    Con la ingestión básica, puedes enviar de forma segura datos desde tus dispositivos o aplicaciones a los servicios de AWS compatibles con las acciones de reglas de AWS IoT sin incurrir en costes de mensajería. La ingestión básica optimiza el flujo de datos eliminando el Message Broker de la ruta de ingestión, lo que lo hace más rentable.

    Los mensajes del Basic Ingest tienen nombres de tema que comienzan con $aws/rules/rule_name para sus tres primeros niveles, donde rule_name es el nombre de la regla de AWS IoT que quieres invocar. Pueden usarse las reglas existentes con Basic Ingest añadiéndoles el prefijo ($aws/rules/rule_name) al tema de la mensaje que normalmente se usaría para invocar las reglas.

    Por ejemplo, si tienes una regla llamada BuildingManager que se invoca mediante mensajes con temas como Buildings/Building5/Floor2/Room201/Lights ("sql": "SELECT * FROM 'Buildings/#'"), puedes invocar la misma regla con Basic Ingest enviando un mensaje al tema $aws/rules/BuildingManager/Buildings/Building5/Floor2/Room201/Lights.

    Para obtener más información sobre Basic Ingest puedes consultar: Reducir los costes de mensajería con Basic Ingest.
