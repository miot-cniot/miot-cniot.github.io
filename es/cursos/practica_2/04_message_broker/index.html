    4. Gestión del tráfico de mensajes: el Message Broker

    Definición de Message Broker

    En la lección anterior, aprendiste que los dispositivos y clientes de IoT pueden comunicarse utilizando un modelo de publicación-suscripción a temas, todo esto utilizando el protocolo MQTT. La información era bastante general para comprender mejor los conceptos. En esta lección, profundizamos un poco más en cómo ocurre esta comunicación y los actores involucrados, particularmente dentro de AWS IoT Core.

    Un ejemplo de broker

    Comencemos con una analogía una vez más. Observa la siguiente imagen que resume el escenario.

    Los actores y elementos implicados son los seguintes:

    • Los aspirantes a cineastas

      Imagina a varias personas que quieren presentar una idea para una película a un productor. Todos tienen una historia diferente que presentar y quieren acceder al despacho del productor.

    • La seguridad

      La primera barrera para acceder es el guardia de seguridad en la puerta principal.

    • La identificación

      Todos deben mostrar alguna forma de identificación reconocida.

    • El mostrador de información

      Una vez que cada persona es autenticada, el siguiente paso es el mostrador de información principal en el vestíbulo. El propósito de la persona en el mostrador no es juzgar el argumento de la película, sino dirigir a las personas al productor adecuado.

    • Los productores

      Según el tipo de película, cada persona se dirige al productor adecuado. Los productores también pueden enviar solicitudes específicas a los aspirantes a cineastas. Productores que quieren guiones de documentales, películas de terror, acción o comedias. El nombre del tema sería como scripts/movies/horror o scripts/movies/action.

    En este ejemplo, el paso de triaje en el mostrador de información es clave para toda la operación. Esa persona desempeña el papel de un broker, dirigiendo el tráfico de aspirantes al destino correcto para entregar su guión. Para recapitular, los componentes de este ejemplo son los siguientes:

    • Aspirantes a cineastas
    • ID
    • Seguridad
    • Mostrador de información
    • Productores

    Adaptando el ejemplo al caso IoT

    Como en la última sección, vamos a hacer la transición de los diversos componentes para llevar este ejemplo al mundo de la IoT.

    Revisa el siguiente diagrama que refleja los cambios que hacemos en el ejemplo.

    Los actores y elementos en el caso IoT son:

    • Los dispositivos IoT

      Reemplacemos a los aspirantes a cineastas con dispositivos y sensores de loT. En lugar de tener guiones de películas, tenemos datos contenidos en mensajes MQTT disponibles para las entidades que se suscribieran a los temas publicados.

    • Certificados y credenciales

      Reemplacemos la ID con el certificado de seguridad y las credenciales necesarias para autenticarse en AWS IoT Core. La comunicación del dispositivo está protegida mediante el uso de protocolos de comunicación MQTT o HTTPS seguros. Estos protocolos utilizan certificados de cliente X.509 proporcionados por AWS IoT para autenticar las conexiones del dispositivo.

    • La pasarela de dispositivos

      Reemplacemos al portero por un componente de IoT Core llamado pasarela de dispositivos (Device Gateway). Permite a los dispositivos comunicarse de forma segura con AWS IoT, recibir ejecuciones de trabajos y actualizar el estado de ejecución del trabajo. La pasarela de dispositivos verifica la autenticación de los diversos dispositivos y clientes conectados a ella. Es uno de los componentes de loT Core responsables de la seguridad.

    • El intermediario de mensajería

      Reemplacemos el mostrador de clasificación por un intermediario de mensajería (Message Broker) que administra la autorización y la clasificación, entrega los mensajes publicados por los dispositivos IoT y entrega una copia a cada entidad que se suscribe al tema. Los mensajes se identifican mediante un tema definido por la aplicación. Cuando el Message Broker recibe un mensaje, vuelve a publicar ese mensaje en los dispositivos y aplicaciones que se suscribieron al tema del mensaje.

    • Los servicios de AWS

      Reemplacemos a los productores por servicios de AWS u otros clientes que se suscribieron a los temas ofrecidos por los dispositivos loT.

    De vuelta al escenario del camión de helados

    En pocas palabras, AWS IoT Message Broker es cómo se comunican los clientes y AWS IoT Core. Los clientes envían datos publicando un mensaje en un tema. Los clientes reciben mensajes suscribiéndose a un tema.

    En nuestro escenario de los helados, un sensor de temperatura puede publicar un mensaje en el tema de la temperatura del congelador principal del camión. El mensaje se retransmite a IoT Core y es manejado por el Message Broker.

    El Message Broker sabe que hay suscripciones para este tema y mantiene una lista de todas las sesiones de cliente y las suscripciones para cada sesión. Cuando se publica un mensaje en un tema, el broker busca sesiones con suscripciones que se mapean al tema. Luego, el broker reenvía el mensaje publicado a todas las sesiones que tienen un cliente conectado actualmente o una sesión persistente.

    Protocolos admitidos

    El Message Broker admite tres protocolos de comunicación: MQTT 3.1.1 y MQTT 5, MQTT a través de Web Sockets y HTTP 1.1. Tanto MQTT como HTTPS son compatibles a través de IPv4 e IPv6.

    La forma de conectarse al Message Broker depende del protocolo que se utilice. Los diferentes protocolos requieren diferentes mecanismos de autenticación. Para obtener más información sobre las diferencias y qué autenticación utiliza cada método, consulta: Protocolos de comunicación de dispositivos.
