    9. Consellos e solución de problemas

    Consello1. Comprobación da versión da CLI

    Comprobación da versión da AWS CLI Para comprobar se tes instalada a AWS CLI e para comprobar a súa versión, executa o seguinte comando

    aws –version

    Deberías ver unha saída similar a:

    aws-cli/2.1.30 Python/3.8.8 Linux/4.14.219-119.340.amzn1.x86_64 exe/x86_64.amzn.2018 prompt/off

    Consello2. Cando vexas "A mensaxe non se pode mostrar no formato especificado." como aviso na consola de AWS IoT.

    Fai clic en Editar e selecciona Mostrar cargas útiles como cadeas (máis preciso)

    Consello3. Arquivo de configuración do cliente de dispositivos AWS IoT - localización?

    Podes ver o arquivo de configuración executando o seguinte comando:

    sudo cat /root/.aws-iot-device-client/aws-iot-device-client.conf

    Se alteras algunha configuración, asegúrate de reiniciar o cliente de dispositivos AWS IoT para que os novos cambios teñan efecto.

    sudo systemctl restart aws-iot-device-client

    Consello4. Compilar un proxy local para AWS IoT Secure Tunneling desde a fonte.

    Configurar dependencias

    • Dependencia de zlibc
    sudo apt install zlibc
sudo apt install cmake
    • Dependencia de Boost

    Primeiro executa isto:

    cd ~/environment/
wget https://boostorg.jfrog.io/artifactory/main/release/1.76.0/source/boost_1_76_0.tar.gz -O /tmp/boost.tar.gz
tar xzvf /tmp/boost.tar.gz
cd boost_1_76_0
./bootstrap.sh

    despois isto:

    sudo ./b2 install link=static
    • Dependencia de Protobuf
    cd ~/environment/
wget https://github.com/protocolbuffers/protobuf/releases/download/v3.17.3/protobuf-all-3.17.3.tar.gz -O /tmp/protobuf-all-3.17.3.tar.gz
tar xzvf /tmp/protobuf-all-3.17.3.tar.gz
cd protobuf-3.17.3
mkdir build
cd build
cmake ../cmake
make
sudo make install
    • Bibliotecas de desenvolvemento de OpenSSL
    sudo apt install libssl-dev
    • Framework de probas Catch2
    cd ~/environment/
git clone --branch v2.13.6 https://github.com/catchorg/Catch2.git
cd Catch2
mkdir build
cd build
cmake ../
make
sudo make install
    • Compilar proxy local Clona e compila o proxy local para o noso dispositivo de orixe.
    cd ~/environment/
git clone https://github.com/aws-samples/aws-iot-securetunneling-localproxy
cd aws-iot-securetunneling-localproxy
mkdir build
cd build
cmake ../
make

    Consello5. Executar o cliente de dispositivos AWS IoT como servizo?

    Comando de inicio

    sudo systemctl start aws-iot-device-client

    Comando de detención

    sudo systemctl stop aws-iot-device-client

    Comando de estado

    sudo systemctl status aws-iot-device-client

    Consello6. Seguimento de rexistros

    Comando de seguimento como root

    sudo tail -F /var/log/aws-iot-device-client/aws-iot-device-client.log

    Consello8. Podes evitar configurar interactivamente o cliente de dispositivos AWS IoT, creando directamente o arquivo de configuración.

    endpoint=$(aws --region us-east-1 iot-describe-endpoint --endpoint-type "iot:Data-ATS" | jq -r .endpointAddress)
crt=$(ls /home/ubuntu/workshop_dc/certs/*.pem.crt)
pvt=$(ls /home/ubuntu/workshop_dc/certs/*-private.pem.key)
rootcert=$(ls /home/ubuntu/workshop_dc/certs/*.pem)

cat >> aws-iot-device-client.conf <<EOL
{
    "endpoint": "$endpoint",
    "cert": "$crt",
    "key": "$pvt",
    "root-ca": "$rootcert",
    "thing-name": "deviceClientThing",
    "logging": {
        "level": "INFO",
        "type": "FILE",
        "file": "/var/log/aws-iot-device-client/aws-iot-device-client.log",
        "enable-sdk-logging": false,
        "sdk-log-level": "TRACE",
        "sdk-log-file": "/var/log/aws-iot-device-client/sdk.log"
    },
    "jobs": {
        "enabled": true,
        "handler-directory": "/etc/.aws-iot-device-client/jobs"
    },
    "tunneling": {
        "enabled": true
    },
    "device-defender": {
        "enabled": true,
        "interval": 300
    },
    "fleet-provisioning": {
        "enabled": false,
        "template-name": "",
        "template-parameters": "",
        "csr-file": "",
        "device-key": ""
    },
    "samples": {
        "pub-sub": {
            "enabled": true,
            "publish-topic": "/topic/workshop/dc/pub",
            "publish-file": "/etc/.aws-iot-device-client/pubsub/publish-file.txt",
            "subscribe-topic": "/topic/workshop/dc/sub",
            "subscribe-file": "/home/ubuntu//workshop_dc/subfile.txt"
        }
    },
    "config-shadow": {
        "enabled": false
    },
    "sample-shadow": {
        "enabled": false,
        "shadow-name": "",
        "shadow-input-file": "",
        "shadow-output-file": ""
    }
}
EOL

sudo cp aws-iot-device-client.conf /etc/.aws-iot-device-client/aws-iot-device-client.conf
sudo mkdir -p /var/log/aws-iot-device-client/

    Consello9. Para acceder á instancia EC2

    1. Navega á pestana Recursos da creación da pila de Cloudformation.

    2. Fai clic na ligazón da instancia EC2 que comeza por "i-xxxxxxx".

    3. Selecciona a caixa de verificación da instancia EC2.

    4. Fai clic en Conectar, selecciona a pestana Xestor de sesións e fai clic en Conectar.
