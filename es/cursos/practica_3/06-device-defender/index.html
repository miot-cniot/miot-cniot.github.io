    7. Auditoría de la seguridad

    AWS IoT Device Defender

    AWS IoT Device Defender es un servicio de seguridad IoT totalmente gestionado que permite proteger las configuraciones IoT de forma continua. AWS IoT Device Defender proporciona herramientas para identificar y responder a problemas de seguridad. Se puede usar AWS IoT Device Defender para:

    • Auditar flotas de dispositivos para garantizar que cumplen con las buenas prácticas de seguridad.

    • Monitorizar métricas de las flotas de dispositivos para detectar cualquier comportamiento anormal.

    • Alertar sobre problemas de seguridad a medida que surgen, por ejemplo, cuando falla una auditoría o se observa una anomalía en las métricas.

    • Desplegar automáticamente acciones de mitigación integradas para abordar los problemas de seguridad que causen alertas.

    Capacidades clave de AWS IoT Device Defender

    Auditoría

    AWS IoT Device Defender audita los recursos relacionados con los dispositivos (como certificados X.509, políticas IoT e identificadores de cliente) frente a las mejores prácticas de seguridad de AWS IoT (p.ej., el principio de privilegio mínimo o la identidad única por dispositivo). La función de auditoría informa de configuraciones que no cumplen las mejores prácticas de seguridad, como por ejemplo que haya varios dispositivos que usen la misma identidad o se usen políticas demasiado permisivas que dejen que un dispositivo lea y actualice datos de otros dispositivos.

    Detección de comportamientos anómalos

    AWS IoT Device Defender detecta comportamientos inusuales de los dispositivos que pueden ser indicativos de una violación al monitorizar continuamente métricas de seguridad del dispositivo y de AWS IoT Core (p.ej., el número de puertos TCP que están a la escucha en los dispositivos o la cantidad de fallos de autorización). La detección puede hacerse usando reglas o modelos ML.

    Aviso

    La funcionalidad de detección de AWS IoT Device Defender ha dejado de estar disponible desde Septiembre de 2026.

    Alertas

    AWS IoT Device Defender publica alarmas en la consola de AWS IoT, Amazon CloudWatch y Amazon SNS.

    Mitigación

    AWS IoT Device Defender permite investigar problemas proporcionando información contextual e histórica sobre el dispositivo, como metadatos, estadísticas e historial de alarmas. También pueden usarse las acciones de mitigación integradas de AWS IoT Device Defender para realizar pasos de mitigación ante alarmas de Auditoría y Detección, como añadir objetos a un grupo de objetos, reemplazar la versión predeterminada de la política o actualizar el certificado del dispositivo.

    Configuración de una auditoría de seguridad

    Esta parte del tutorial se centra en la demostración práctica del uso de AWS IoT Device Defender para realizar una auditoría de seguridad y corregir las anomalías detectadas. Las auditorías pueden ser programadas (se repiten regularmente de manera automática) o puntuales.

    Las auditorías de AWS IoT Device Defender examinan la configuración y las políticas relacionadas con la cuenta y el dispositivo para garantizar que las medidas de seguridad estén implementadas adecuadamente. Una auditoría puede ayudar a detectar cualquier desviación de las mejores prácticas de seguridad o políticas de acceso (p.ej., varios dispositivos que usen la misma identidad, o el uso de políticas demasiado permisivas que permitan que un dispositivo lea y actualice datos de otros dispositivos)

    Para crear una auditoría de seguridad haz lo siguiente:

    1. En el menú de la izquierda en la consola del AWS IoT Core selecciona: Administrar → Seguridad → Auditoría y haz clic en el botón Automatice la auditoría de seguridad de IoT

      Creación de una auditoría programada

      Esto crea una auditoría que se ejecutará automáticamente con una periodicidad diaria.

    2. Para crear una auditoría puntual, selecciona en el menú de la izquierda en la consola de AWS IoT Core: Administrar → Seguridad → Auditoría → Programaciones y haz clic en el botón Crear en la parte superior derecha.

      Nota

      En algunos navegadores, el menú izquierdo de la consola puede no mostrar los subelementos bajo Seguridad → Auditoría inmediatamente después de activar la auditoría. Si no ves el elemento Programaciones bajo Auditoría, actualiza la ventana del navegador.

    3. En el asistente para crear una nueva auditoría, deja todas las configuraciones predeterminadas y haz clic en Crear para aceptar la creación de la auditoría.

    4. Una vez que se crea la auditoría, espera mientras su estado sea En progreso (puede tardar unos minutos). Para actualizar el estado de la auditoría puedes hacer clic en el botón Actualizar en la parte superior derecha. Una vez que termine, selecciona Bajo demanda.

    5. Vemos que dos de las buenas prácticas de seguridad comprobadas fallaron.

    En los siguientes apartados vamos a resolver las incidencias encontradas.

    Política excesivamente permisiva

    1. Selecciona la primera de las incidencias: Políticas de IoT excesivamente permisivas, para ver sus detalles.

      Nota

      Anteriormente creamos para el tutorial la política IoT workshopDC, que permite todas las acciones IoT sobre cualquier recurso. Esto no cumple con el Principio de Privilegio Mínimo.

    2. Selecciona la política workshopDC, haz clic en Editar versión activa y cambia a la vista JSON para editarla.

    3. Copia la siguiente política en el panel JSON del documento de la política.

      Nota

      Cambia <ACCOUNT NUMBER> por tu número de cuenta y, si has usado temas MQTT diferentes, también habrá que editarlos.

      {
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "iot:Publish",
                "iot:Receive"
            ],
            "Resource": [
                "arn:aws:iot:us-east-1:<ACCOUNT NUMBER>:topic/$aws/things/${iot:Connection.Thing.ThingName}/*",
                "arn:aws:iot:us-east-1:<ACCOUNT NUMBER>:topic/workshop/zt/pub"
            ]
        },
        {
            "Effect": "Allow",
            "Action": [
                "iot:Subscribe"
            ],
            "Resource": [
                "arn:aws:iot:us-east-1:<ACCOUNT NUMBER>:topicfilter/$aws/things/${iot:Connection.Thing.ThingName}/*",
                "arn:aws:iot:us-east-1:<ACCOUNT NUMBER>:topicfilter/workshop/zt/sub"
            ]
        },
        {
            "Effect": "Allow",
            "Action": [
                "iot:Connect"
            ],
            "Resource": [
                "arn:aws:iot:us-east-1:<ACCOUNT NUMBER>:client/${iot:Connection.Thing.ThingName}"
            ]
        }
    ]
}

    4. Selecciona la opción Establecer esta versión como versión activa y haz clic en el botón Guardar nueva versión para crear la versión modificada de la política IoT.

    Activación de los registros (logging)

    Vamos ahora a resolver la segunda de las incidencias. Haz lo siguiente:

    1. Vuelve a los resultados de la auditoría bajo demanda que ejecutamos anteriormente y selecciona la segunda incidencia: Registro desactivado

      Nota

      Aún verás la incidencia Políticas de IoT excesivamente permisivas en el listado, ya que muestra los resultados de la auditoría realizada antes de que modificáramos la política.

    2. Desde los detalles de la incidencia, abre la configuración de los registros haciendo clic en el enlace del número de cuenta.

    3. En el apartado de Registros haz clic en el botón Gestionar registros.

    4. Configura las siguientes propiedades de los logs:

      • Rol de log: selecciona el rol Labrole predefinido.
      • Nivel de log: selecciona DEBUG.

      Haz clic en Actualizar para guardar las modificaciones.

      Debería verse el mensaje Registro actualizado con éxito.

    Repetir la auditoría para verificar

    Vamos ahora a repetir la auditoría para comprobar si las configuraciones realizadas solucionaron las incidencias.

    1. Vuelve a crear una nueva auditoría ad hoc eligiendo en el menú de la izquierda en la consola del AWS IoT Core: Gestionar → Seguridad → Auditoría → Programaciones y haciendo clic en el botón Crear en la parte superior derecha.

    2. Deja todas las configuraciones predeterminadas y haz clic en Crear para aceptar la creación de la auditoría.

    3. Una vez que la auditoría termine, comprueba que esta vez el dispositivo ha pasado la comprobación con éxito.
