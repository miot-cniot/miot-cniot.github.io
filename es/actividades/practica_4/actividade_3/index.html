    Actividad 3

    COMPONENTES PERSONALIZADOS DE APRENDIZAJE AUTOMÁTICO

    Aviso

    Para poder realizar esta actividad es obligatorio realizar previamente la actividad 2.

    Objetivo

    El objetivo de esta actividad es crear un componente personalizado para la ejecución de modelos de aprendizaje automático (ML). A partir del componente de inferencia de la actividad anterior (aws.greengrass.DLRImageClassification) vamos a crear una versión modificada que se suscriba a un tópico IPC predefinido en el que espere recibir mensajes JSON con el siguiente esquema: 

    {
    "image": "<archivo_jpeg>"
}
    Cada vez que reciba un mensaje en el tópico IPC, el componente accederá en el directorio predefinido a la imagen indicada en el mensaje, hará una inferencia con ella y publicará el resultado de la inferencia en el tópico MQTT predefinido.

    Nota

    Puedes ver aquí la documentación sobre la implementación de componentes ML personalizados.

    Importante

    En esta actividad se usa la CLI de AWS. Para que funcione correctamente tienes que tener configuradas tus credenciales con aws configure (mira en la sección 2 del enunciado de la práctica cómo hacerlo si no te acuerdas).

    Creación del componente de inferencia ML personalizado

    Para crear el componente haz lo siguiente en la instancia VSCode:

    1. Descarga la receta del componente proporcionado por AWS en el directorio de recetas.

      Nota

      Los siguientes comandos descargan la receta desde el servicio Greengrass usando la CLI de AWS.

      $ cd ~/environment/GreengrassCore/recipes
$ DLR_INFERENCE_ARN=$(aws greengrassv2 list-components \
    --scope PUBLIC \
    --query 'components[?componentName==`aws.greengrass.DLRImageClassification`]' | jq -r '.[0].arn')
$ DLR_INFERENCE_VERSION_ARN=$(aws greengrassv2 list-component-versions \
    --arn $DLR_INFERENCE_ARN \
    --query 'componentVersions[0].arn' \
    --output text)
$ DLR_INFERENCE_VERSION=$(echo $DLR_INFERENCE_VERSION_ARN | awk -F: '{print $NF}')
$ aws greengrassv2 get-component \
    --arn $DLR_INFERENCE_VERSION_ARN \
    --recipe-output-format JSON \
    --query recipe \
    --output text | base64 --decode | jq '.' > aws.greengrass.DLRImageClassification-$DLR_INFERENCE_VERSION.json

      Descarga de la receta del componente de AWS.

    2. Descarga la receta modificada que vamos a usar para el componente personalizado. 

      $ wget -O com.example.CustomDLRImageClassification-1.0.0.json https://miot-cniot.github.io/actividades/practica_4/stuff/CustomDLRImageClassification-1.0.0.json

      Importante

      Edita la receta e introduce tu nombre en el campo ComponentPublisher.

      Descarga de la receta modificada.

    3. Compara las recetas y comprueba los cambios que se hicieron para adaptarla a nuestro ejemplo. Los principales fueron:

      • Se redujo el número de plataformas soportadas por el componente a la única que nos interesa para el ejemplo.
      • Se añadieron a la configuración una política de control de acceso para los tópicos IPC y un parámetro LocalTopic para configurar el tópico IPC a usar.

    4. Comprueba los artefactos del componente proporcionado por AWS que están instalados en la instancia VSCode. 

      $ sudo ls -l /greengrass/v2/packages/artifacts-unarchived/aws.greengrass.DLRImageClassification/$DLR_INFERENCE_VERSION/image_classification/

      Artefactos del componente DLRImageClassification.

    5. Crea el directorio para los artefactos del componente personalizado. 

      $ mkdir -p ~/environment/GreengrassCore/artifacts/com.example.CustomDLRImageClassification/1.0.0 && cd ~/environment/GreengrassCore/artifacts/com.example.CustomDLRImageClassification/1.0.0

    6. Copia los ficheros Python del componente proporcionado por AWS al directorio de artefactos del componente personalizado y configura los permisos. 

      $ sudo cp /greengrass/v2/packages/artifacts-unarchived/aws.greengrass.DLRImageClassification/$DLR_INFERENCE_VERSION/image_classification/*.py .
$ sudo chown ubuntu:ubuntu *.py
$ chmod 664 *.py

      Artefactos del componente personalizado.

    7. Descarga el fichero inference.py modificado para el componente personalizado. 

      $ mv inference.py inference.1.py
$ wget https://miot-cniot.github.io/actividades/practica_4/stuff/inference.py

      Ficheros inference del componente personalizado.

    8. Abre ambos ficheros inference y comprueba los cambios que se hicieron para adaptarlo a nuestro ejemplo. Los principales fueron:

      • Se añadió el código que realiza la subscripción al tópico IPC.
      • Se definió un handler (InferenceRequestHandler) para procesar los eventos de la subscripción IPC. La parte más relevante del handler es el método on_stream_event que es el que procesa los mensajes que se reciben en el tópico y hace una inferencia si procede.

      Nota

      Presta atención a que el código añadido en inference.py es similar al del Subscriber que se vió en la sección 5 del curso.

    9. Una vez termines de comprobar las diferencias, elimina la copia inference.1.py.

    10. Crea un directorio para las imágenes y descarga la imagen de prueba. 

      $ mkdir ~/environment/image_classification && cd ~/environment/image_classification
$ wget https://raw.githubusercontent.com/awslabs/aws-greengrass-labs-ml-components/main/dlr/aws.greengrass.DLRImageClassification/image_classification/sample_images/cat.jpeg

      Contenido del directorio de imágenes.

    Despliegue del componente

    1. Comprueba que ninguno de los componentes desplegados en la instancia esté en estado BROKEN. Si hubiera algún componente local (no desplegado desde AWS IoT) en estado BROKEN, puedes reiniciarlo o eliminarlo. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep BROKEN -B 2 -A 1

    2. En la consola de AWS IoT haz un nuevo despliegue en el dispositivo Greengrass edgeDevice que solo contenga el componente aws.greengrass.Cli.

    3. Asegúrate de que el despliegue terminó correctamente y de que la única dependencia del componente aws.greengrass.DLRImageClassification que queda en el dispositivo es el despliegue local del runtime de DLR. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3

      Resultado de la comprobación.

    4. Comprueba de nuevo que no haya ningún componente en la instancia en estado BROKEN después del despliegue.

    5. En el cliente MQTT de la consola de AWS IoT suscríbete al tópico ml/custom/image-classification, en el que el componente personalizado publicará los resultados de las inferencias.

    6. Despliega el componente de inferencia ML personalizado. 

      $ sudo /greengrass/v2/bin/greengrass-cli deployment create \
    --recipeDir ~/environment/GreengrassCore/recipes \
    --artifactDir ~/environment/GreengrassCore/artifacts \
    --merge "com.example.CustomDLRImageClassification=1.0.0"

    7. Comprueba que el despliegue terminó correctamente. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3  
$ sudo tail -5 /greengrass/v2/logs/com.example.CustomDLRImageClassification.log

      Resultado de la comprobación.

    8. Comprueba también si se recibió en el cliente MQTT de la consola AWS IoT el resultado de la inferencia en el tópico ml/custom/image-classification.

      Mensaje recibido en el tópico MQTT.

    Nota

    Si los pasos 7 u 8 no dan los resultados esperados, comprueba en el log del Greengrass si hubo errores durante el despliegue del componente. Puedes consultar aquí los errores más comunes.

    Verificación del funcionamiento

    1. Abre un nuevo terminal en la instancia VSCode y suscríbete al tópico IPC ml/image. Mantén este terminal abierto. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub sub -t="ml/image"
Successfully subscribed to topic: ml/image

    2. Desde otro terminal diferente publica un mensaje en el tópico ml/image. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub pub -m="{\"image\": \"cat.jpeg\"}" -t="ml/image"

      Mensaje publicado en el tópico IPC.

      Nota

      En el terminal en el que ejecutaste la subscripción aparecerá el mensaje {"image": "cat.jpeg"} que tiene el formato JSON que el componente espera recibir y el nombre de la imagen con la que se realiza la inferencia.

    3. Comprueba que en el cliente MQTT de la consola AWS IoT se recibió en el tópico ml/custom/image-classification un segundo mensaje con el resultado de la inferencia.

    4. Descarga otra imagen en el directorio de imágenes. 

      $ cd ~/environment/image_classification
$ wget -O cat2.jpeg https://www.publicdomainpictures.net/pictures/90000/velka/cat-14022476612Gk.jpg

      Contenido del directorio de imágenes.

      Nota

      Puedes ver aquí la imagen descargada.

    5. Publica el mensaje con el nombre del nuevo archivo y comprueba que se reciba en el cliente MQTT el resultado de la inferencia. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub pub -m="{\"image\": \"cat2.jpeg\"}" -t="ml/image"

      Mensaje con el resultado de la inferencia.

    6. Si quieres puedes hacer más pruebas descargando otras imágenes y publicando su nombre.

    Publicación y despliegue del componente

    Vamos ahora a publicar el componente para poder desplegarlo desde AWS IoT. Haz lo siguiente:

    1. Crea un bucket S3 para subir los artefactos y la receta del componente. 

      $ AWS_DEFAULT_REGION=us-east-1 && \
    EPOCH_TIME=$(date +"%s") && \
    S3_BUCKET=ggcv2-workshop-$HOSTNAME-$EPOCH_TIME && \
    aws s3 mb s3://$S3_BUCKET --region $AWS_DEFAULT_REGION
make_bucket: ggcv2-workshop-ip-172-31-80-21-1761214805

    2. Edita la receta del componente com.example.CustomDLRImageClassification y cambia el manifiesto por el siguiente.

      Manifests
      "Manifests": [
    {
      "Platform": {
        "os": "linux",
        "architecture": "amd64"
      },
      "Lifecycle": {
        "setEnv": {
          "DLR_IC_MODEL_DIR": "{variant.DLR.ImageClassification.ModelStore:artifacts:decompressedPath}/{configuration:/ModelResourceKey/x86_64}",
          "DEFAULT_DLR_IC_IMAGE_DIR": "/home/ubuntu/environment/image_classification/",
          "TOPIC": "{configuration:/LocalTopic}"
        },
        "run": {
          "RequiresPrivilege": "true",
          "script": "\n                                    export PATH=\"{variant.DLR:configuration:/MLRootPath}/greengrass_ml_dlr_conda/bin:$PATH\"\n                                    eval \"$({variant.DLR:configuration:/MLRootPath}/greengrass_ml_dlr_conda/bin/conda shell.bash hook)\"\n                                    conda activate greengrass_ml_dlr_conda\n                                    python3 {artifacts:decompressedPath}/custom/inference.py"
        }
      },
     "Artifacts": [
        {
           "URI": "s3://[EL_NOMBRE_DE_TU_BUCKET]/artifacts/com.example.CustomDLRImageClassification/1.0.0/custom.zip",
           "Unarchive": "ZIP"
        }
     ]
    }
],

      Los cambios que se hicieron fueron:

      • Se añadió el objeto Artifacts para descargar los artefactos de S3.

        Importante

        Recuerda editar en la URI el nombre de tu bucket.

      • En el script se cambió la localización del fichero inference.py de {artifacts:path} a {artifacts:decompressedPath}/custom para usar la ruta en la que Greengrass descomprime el fichero descargado de S3.

    3. Comprime los artefactos del componente y sube el fichero comprimido y la receta al bucket S3. 

      $ sudo apt install zip
$ cd ~/environment/GreengrassCore
$ ARTIFACTS_DIR="./artifacts/com.example.CustomDLRImageClassification/1.0.0"
$ zip -j $ARTIFACTS_DIR/custom.zip $ARTIFACTS_DIR/*.py
$ aws s3 cp $ARTIFACTS_DIR/custom.zip s3://$S3_BUCKET/artifacts/com.example.CustomDLRImageClassification/1.0.0/
$ aws s3 cp ./recipes/com.example.CustomDLRImageClassification-1.0.0.json s3://$S3_BUCKET/recipes/

      Subida a S3 de los artefactos y la receta.

    4. Comprueba que los contenidos del bucket S3 son correctos. 

      $ aws s3 ls --recursive s3://$S3_BUCKET

      Resultado de la comprobación.

    5. Crea el componente en el AWS IoT Core. 

      $ cd ~/environment/GreengrassCore/recipes
$ aws greengrassv2 create-component-version --inline-recipe fileb://com.example.CustomDLRImageClassification-1.0.0.json --region $AWS_DEFAULT_REGION

      Resultado de la creación del componente.

    6. Comprueba que aparece en el listado de componentes. Compruébalo también en la consola de AWS IoT. 

      $ aws greengrassv2 list-components --region $AWS_DEFAULT_REGION --query='components[?componentName==`com.example.CustomDLRImageClassification`]'

      Resultado de la comprobación en la instancia VSCode.

      Resultado de la comprobación en el AWS IoT.

    7. Elimina el componente desplegado localmente. Asegúrate de que la única dependencia del componente que queda en el dispositivo es el despliegue local del runtime de DLR. 

      $ sudo /greengrass/v2/bin/greengrass-cli --ggcRootPath /greengrass/v2 deployment create --remove "com.example.CustomDLRImageClassification"  
$ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3

      Resultado de la eliminación del componente.

    8. Asegúrate de que no haya ningún componente en la instancia en estado BROKEN.

    9. En la consola de AWS IoT haz un nuevo despliegue en el dispositivo Greengrass edgeDevice que contenga solo los componentes aws.greengrass.Cli y com.example.CustomDLRImageClassification.

      Componente personalizado desplegado desde AWS IoT.

    10. Comprueba en la consola de AWS IoT y en la instancia que el despliegue termine correctamente.

      Resultado de la comprobación en la instancia VSCode.

    11. Verifica el funcionamiento correcto del componente repitiendo los pasos de la sección de verificación.

    Justificación de la actividad

    Toma las siguientes capturas para la memoria de justificación de la práctica:

    1. Consola de AWS IoT mostrando las propiedades del último despliegue en el dispositivo edgeDevice con la pestaña Componentes escogida, de modo que pueda verse que el componente com.example.CustomDLRImageClassification fue desplegado.

    2. Instancia VSCode en la que puedan verse en el árbol de directorios los artefactos y receta del componente com.example.CustomDLRImageClassification y los contenidos del directorio image_classification, y además:

      • La salida del terminal en el que se ejecutó el comando de subscripción al tópico ml/image.
      • La salida del terminal desde el que se publicaron los mensajes en el tópico ml/image.
      • La salida de la ejecución de los comandos:
      $ aws s3 ls --recursive s3://$S3_BUCKET
$ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3
$ sudo tail -3 /greengrass/v2/logs/com.example.CustomDLRImageClassification.log

      Nota

      El último comando tiene que ejecutarse después de completar una inferencia y tiene que mostrar los mensajes del log que indican que se enviaron los resultados de la inferencia al AWS IoT Core (si es preciso modifica la cantidad de líneas mostradas).

      Ejemplo

    3. Consola de AWS IoT con el mensaje MQTT recibido en el tópico ml/custom/image-classification para el archivo cat2.jpeg, en la que pueda verse el payload.

      Nota

      El mensaje tiene que ser de una inferencia realizada por el componente desplegado desde AWS IoT, es decir, no vale el mensaje del paso 5 de la sección de verificación que se hace por primera vez con el componente desplegado localmente.

    Importante

    Las capturas tienen que asemejarse a las que se tomaron en el curso y en las prácticas anteriores. Las capturas tomadas en la consola AWS tienen que incluir el menú superior en el que pueda verse el nombre de usuario de la cuenta.
