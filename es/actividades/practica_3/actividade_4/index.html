    Actividad 4

    IMPLEMENTACIÓN DE UN MANEJADOR DE TRABAJOS (JOB HANDLER).

    Objetivo

    El objetivo de esta actividad es implementar un manejador de trabajos (Job Handler) en el dispositivo IoT.

    El manejador consistirá en un script que publique la configuración del dispositivo en un mensaje MQTT usando la funcionalidad de mensajería MQTT del Device Client que vimos en una actividad anterior.

    Nota

    Puedes ver aquí la documentación sobre los manejadores de trabajos del AWS IoT Device Client.

    Creación del manejador de trabajos

    Para crear el manejador de trabajos haz lo siguiente:

    1. En la instancia VSCode deviceClient en la que está instalado el Device Client comprueba en la configuración de los trabajos cuál es el directorio en el que se almacenan los manejadores.

      $ sudo cat /etc/.aws-iot-device-client/aws-iot-device-client.conf | jq '.jobs'
{
  "enabled": true,
  "handler-directory": "/etc/.aws-iot-device-client/jobs"
}

    2. Comprueba cuáles son los manejadores disponibles.

      $ HANDLER_DIR=$(sudo cat /etc/.aws-iot-device-client/aws-iot-device-client.conf | jq -r '.jobs."handler-directory"')
$ sudo ls $HANDLER_DIR 
download-file.sh  install-packages.sh  remove-packages.sh   shutdown.sh        stop-services.sh              verify-packages-removed.sh
health-check.sh   reboot.sh            restart-services.sh  start-services.sh  verify-packages-installed.sh

    3. En la sección 5.2 del curso, el trabajo que descargaba un fichero en el dispositivo IoT se creó a partir de la plantilla de documento de trabajo AWS-Download-File gestionada por AWS. Esta plantilla es de tipo runHandler y ejecuta en el dispositivo IoT el manejador download-file.sh pasándole como parámetros la URL del fichero y el directorio en el que descargarlo.

      {
  "version": "1.0",
  "steps": [
    {
      "action": {
        "name": "Download-File",
        "type": "runHandler",
        "input": {
          "handler": "download-file.sh",
          "args": [
            "${aws:iot:parameter:downloadUrl}",
            "${aws:iot:parameter:filePath}"
          ],
          "path": "${aws:iot:parameter:pathToHandler}"
        },
        "runAsUser": "${aws:iot:parameter:runAsUser}"
      }
    }
  ]
}

      Comprueba cómo es la implementación de este manejador:

      $ sudo cat $HANDLER_DIR/download-file.sh
#!/usr/bin/env sh
set -e

echo "Running download-file.sh"
user=$1
fileUrl=$2
outputFile=$3
echo "Username: $user"
echo "File URL: $fileUrl"
echo "Write documents to file: $outputFile"
if command -v "wget" > /dev/null
then
    echo "Using wget for downloading user specified file"
    if id "$user" 2>/dev/null && command -v "sudo" > /dev/null; then
      if [ -d "$outputFile" ]; then
        sudo -u "$user" -n wget --quiet -P "$outputFile" "$fileUrl"
      else
        sudo -u "$user" -n wget --quiet -O "$outputFile" "$fileUrl"
      fi
    else
      echo "username or sudo command not found"
      if [ -d "$outputFile" ]; then
        wget --quiet -P "$outputFile" "$fileUrl"
      else
        wget --quiet -O "$outputFile" "$fileUrl"
      fi
    fi
else
    >&2 echo "Wget software package not installed on the device. Use the \"install-packages.sh\" operation to install the wget software package on this device."
    exit 1
fi

      Como puedes ver se trata de un script que recibe 3 de los parámetros de entrada definidos en la plantilla:

      • la cuenta de usuario que se va a usar para ejecutar el script
      • la URL del fichero
      • el directorio en el que guardarlo

      y utiliza el comando wget para descargar el fichero en el directorio que se le indica.

      Puedes curiosear en las implementaciones de los otros manejadores.

      Nota

      Si lo prefieres, también puedes ver aquí la implementación de los manejadores instalados por defecto.

    4. Comprueba que la mensajería MQTT está activada y cuáles son el tema y fichero de publicación.

      $ sudo cat /etc/.aws-iot-device-client/aws-iot-device-client.conf | jq '.samples'
{
  "pub-sub": {
    "enabled": true,
    "publish-topic": "/topic/workshop/dc/pub",
    "publish-file": "/home/ubuntu/workshop_dc/pubfile.txt",
    "subscribe-topic": "/topic/workshop/dc/sub",
    "subscribe-file": "/home/ubuntu/workshop_dc/subfile.txt",
    "publish-on-change": true
  }
}

    5. Crea un manejador que publique la configuración del Device Client como mensaje MQTT.

      • Crea el script del manejador en el directorio donde se guardan los manejadores.

        $ sudo touch $HANDLER_DIR/device-client-config.sh
$ sudo chmod 700 $HANDLER_DIR/device-client-config.sh

      • Edita el script (p.ej. con sudo nano $HANDLER_DIR/device-client-config.sh) y copia el código siguiente.

        device-client-config.sh
        #!/usr/bin/env sh
set -e

echo "Running device-client-config.sh"
USER=$1
echo "Username: $USER"

if id "$USER" 2> /dev/null && command -v "sudo" > /dev/null; then

    # get publish file from configuration
    PUBFILE=$(cat /etc/.aws-iot-device-client/aws-iot-device-client.conf | jq -e -r '.samples."pub-sub"."publish-file"')
    STATUS=$?

    # check for publish file
    if [ $STATUS -eq 0 ] && sudo -u $USER -n test -f "$PUBFILE"; then
        # write config to publish file
        sudo -u $USER -n cat /etc/.aws-iot-device-client/aws-iot-device-client.conf | jq '{"conf": .}' > $PUBFILE
    else
        echo "A valid publish file was not found in the configuration"
        exit $STATUS
    fi

else
    echo "username or sudo command not found"
    exit 1
fi

        Puedes comprobar en el script que lo que hace es obtener de la configuración del Device Client el nombre del fichero de publicación (lo guarda en PUBFILE), y publicar en él la configuración del Device Client dentro del objeto JSON conf.

    Creación de una plantilla de documento de trabajo personalizado

    Vamos ahora a crear una plantilla de documento de trabajo personalizado para usar con el manejador. Haz lo siguiente:

    1. En la instancia VSCode deviceClient crea en el directorio /home/ubuntu/workshop_dc un fichero deviceConfJobTemplate.json y copia en él la siguiente plantilla de trabajo.

      deviceConfJobTemplate.json
      {
  "version": "1.0",
  "steps": [
    {
      "action": {
        "name": "Get-Configuration",
        "type": "runHandler",
        "input": {
          "handler": "device-client-config.sh",
          "path": "default"
        },
        "runAsUser": "root"
      }
    }
  ]
}

      Nota

      En la sección 8.1 del curso, se usó un documento de trabajo con el siguiente esquema:

      Para la plantilla deviceConfJobTemplate.json estamos usando una versión más reciente del esquema del documento de trabajo. Puedes ver aquí la documentación de ambos esquemas, y aquí y aquí ejemplos de documentos que usan la versión antigua y la más reciente respectivamente.

    2. Sube la plantilla al bucket S3 workshop-dc-bucket (el que se usó en el curso).

      Nomenclatura

      Usa tu prefijo delante del nombre del bucket.

      $ aws s3 cp deviceConfJobTemplate.json s3://<TU_PREFIJO>-workshop-dc-bucket

    3. En la consola de AWS IoT escoge la opción Plantillas de trabajo dentro del menú Acciones remotas.

    4. Con la pestaña Plantillas personalizados escogida, crea una nueva plantilla de trabajo escogiendo Crear plantilla de trabajo e indicando las opciones siguientes:

      • Nombre de la plantilla de trabajo: deviceConfigTemplate. Recuerda poner tu prefijo delante, p.ej. xcpm2425-deviceConfigTemplate.
      • Descripción: introduce una descripción para la plantilla.
      • Documento de trabajo: pulsa en el botón Examinar S3 y escoge el documento JSON que subiste a S3.

      Configuración de la plantilla de documento de trabajo.

    Creación de un trabajo a partir de la plantilla

    1. En el cliente MQTT de la consola de AWS IoT suscríbete a los temas:

      • /topic/workshop/dc/pub
      • $aws/events/job/deviceConfig/completed
      • $aws/events/jobExecution/deviceConfig/succeeded

    2. En la instancia VSCode asegúrate de que el servicio Device Client esté levantado correctamente.

      $ sudo systemctl status aws-iot-device-client

    3. Abre una segunda consola AWS IoT para crear el trabajo en una ventana diferente a la del cliente MQTT del paso anterior. En esta consola escoge la opción Plantillas de trabajo dentro del menú Acciones remotas y abre las propiedades de la plantilla deviceConfigTemplate pulsando en su nombre.

    4. Crea un nuevo trabajo a partir de esta plantilla pulsando en Crear trabajo con esta plantilla e indicando las opciones siguientes:

      • Nombre del trabajo: deviceConfig.
      • Descripción: introduce una descripción para el trabajo.
      • Objetos para ejecutar este trabajo: escoge deviceClientThing.
      • Documento de trabajo: no tienes que hacer nada. Los datos de la plantilla deviceConfigTemplate ya están cubiertos.
      • Tipo de ejecución del trabajo: escoge Instantáneo.

      Configuración del trabajo.

    Verificación de la ejecución del trabajo

    1. Comprueba en la consola del AWS IoT que el trabajo se ejecutó correctamente.

      Ejecución correcta del trabajo en la consola IoT.

    2. Comprueba también que el documento del trabajo es el que definimos en la plantilla.

      Documento del trabajo.

    3. Comprueba que se recibió la configuración del dispositivo en el tema /topic/workshop/dc/pub. Comprueba también los mensajes del trabajo recibidos en los otros temas del cliente MQTT.

      Mensaje recibido con la configuración del dispositivo.

    4. Y finalmente, comprueba que aparezca la ejecución del trabajo en el log de la instancia VSCode.

      Mensaje en el log de la instancia VSCode.

    Justificación de la actividad

    Toma las siguientes capturas para la memoria de justificación de la práctica:

    1. Instancia VSCode deviceClient en la que se vea la salida de la ejecución de los comandos siguientes:

      $ cat deviceConfJobTemplate.json
$ aws s3 ls s3://<TU_PREFIJO>-workshop-dc-bucket
$ sudo cat $HANDLER_DIR/device-client-config.sh

    2. En la consola IoT las propiedades de la plantilla de documento de trabajo deviceConfigTemplate.

      Con que se vea el apartado de detalles es suficiente, los de las configuraciones no hacen falta.

    3. En la consola IoT las propiedades del trabajo deviceConfig con la ejecución finalizada correctamente.

    4. Cliente MQTT en la consola IoT en el que pueda verse el contenido de la configuración recibida en el tema /topic/workshop/dc/pub.

    Importante

    Las capturas tienen que asemejarse a las que se tomaron en el curso y en las prácticas anteriores. Las capturas tomadas en la consola AWS tienen que incluir el menú superior en el que pueda verse el nombre de usuario de la cuenta.
