    Actividad 1

    CREAR UNA REGLA PARA GUARDAR DATOS EN DYNAMODB.

    Objetivo

    El objetivo de esta actividad es crear una regla AWS IoT que envíe los datos de los mensajes de telemetría recibidos desde el dispositivo IoT (el camión) a una tabla DynamoDB.

    Creación de la tabla DynamoDB

    La tabla va a contener los siguientes atributos:

    • sample_time la hora en que el mensaje fue registrado.
    • device_id identificador del camión que transmitió el mensaje.
    • device_data contenido del mensaje formateado por la instrucción SQL de la regla.

    Para crear la tabla haz lo siguiente:

    1. Abre la consola de DynamoDB y escoge la opción Crear tabla.

    2. En el asistente de creación de la tabla indica las opciones siguientes:

      • Nombre de la tabla: trucks-data. Recuerda poner tu prefijo delante, p.ej. xcpm2425-trucks-data.
      • Clave de partición: sample_time de tipo Número.
      • Clave de ordenación: device_id de tipo Número.

    3. Crea la tabla pulsando en el botón Crear tabla

    Nota

    device_data se definirá posteriormente, cuando se configure la acción de la regla AWS IoT.

    Configuración de la tabla DynamoDB.

    Creación de la regla AWS IoT

    La regla va a filtrar y formatear los datos de los mensajes de telemetría recibidos desde el camión y los va a grabar en la tabla de DynamoDB.

    La carga útil (payload) de un mensaje contiene la siguiente información:

    {
  "uptime": "43",
  "volts": "12.08",
  "temp": "15.18",
  "door": "0",
  "i": "1",
  "n": "15",
  "timestamp": 1721929699.2319772
}

    La regla la va a convertir al formato siguiente que será el grabado en la tabla:

    {
  "temperature": "15.18",
  "door": "0"
}

    En la regla vamos a usar modelos de substitución, que son expresiones que permiten insertar valores dinámicos de funciones y datos de mensajes.

    Para crear la regla AWS IoT haz lo siguiente:

    1. Abre la consola AWS IoT y escoge en el panel de la izquierda la opción Reglas en el submenú Enrutamiento de mensajes.

    2. Crea una nueva regla pulsando en Crear regla e indicando las opciones siguientes:

      • Nombre de la regla: truck2ddb. Recuerda poner tu prefijo delante. Usa el caracter de subrayado para separarlo del nombre, ya que no se permiten guiones, p.ej. xcpm2425_truck2ddb.
      • Descripción: pon una descripción para la regla.

      • Instrucción SQL:

        SELECT cast(temp AS DECIMAL) AS temperature, 
       cast(door AS BOOLEAN) AS door 
FROM 'truck/freezer'

        Nota

        Esta instrucción selecciona los atributos temp y door de los mensajes recibidos en el tema truck/freezer, interpreta sus valores con el tipo de dato que les corresponde y renombra temp como temperature y door lo deja con el mismo nombre.

      • Acciones de la regla: en la acción 1 escoge DynamoDB. En los campos que aparecen indica lo siguiente:

        • Nombre de la tabla: escoge trucks-data.
        • Clave de partición: inserta sample_time.
        • Tipo de clave de partición: escoge NÚMERO.
        • Valor de la clave de partición: inserta ${timestamp()}. Esta expresión usa un modelo de substitución para obtener el tiempo actual usando la función timestamp.
        • Clave de ordenación: inserta device_id.
        • Tipo de clave de rango: escoge NÚMERO.

        • Valor de la clave de rango: inserta ${i}.

          Note

          Esta expresión usa un modelo de substitución para tomar el valor del campo i del mensaje como ID del dispositivo. Una alternativa común es que los ID de los dispositivos se incluyan en los nombres de los temas MQTT, p.ej. truck/id/freezer. En ese caso la expresión a usar sería: ${cast(topic(2) as DECIMAL)}, que toma el valor del nivel 2 en el nombre del tema y lo convierte a un valor numérico.

        • Escritura de datos del mensaje en esta columna: introduce device_data. Eso creará una columna device_data en la tabla del DynamoDB para almacenar el mensaje una vez procesado por la regla.

        • Rol de IAM: escoge el rol predefinido LabRole. Este rol ya tiene los permisos necesarios para que la regla envíe los datos a la tabla DynamoDB.

        Configuración de la acción.

    Prueba de la regla AWS IoT

    Para probar el funcionamiento de la regla haz lo siguiente:

    1. En un terminal de la instancia VSCode truckSensor ejecuta el script start.sh.
    2. En el cliente MQTT de la consola de AWS IoT suscríbete al tema truck/freezer y comprueba que se reciben mensajes desde el dispositivo IoT.

    3. En una ventana diferente a la del cliente MQTT, abre la consola de DynamoDB, y haz lo siguiente:

      • Escoge la opción Explorar Elementos en el menú lateral y selecciona la tabla trucks-data.
      • Con la opción Examen escogida, pulsa en el botón Ejecutar y comprueba las entradas que la acción DynamoDB de la regla insertó en la tabla.

      • Actualiza la vista de elementos para comprobar que se van añadiendo nuevas entradas en la tabla a medida que se reciben mensajes en el tema truck/freezer.

        Entradas añadidas en la tabla DynamoDB.

      • Pulsa en el valor del sample_time de uno de los elementos para abrirlo en el editor de elementos. Desde el editor es posible modificar los valores de los atributos del elemento y de los campos de la carga útil del mensaje, así como añadir y eliminar atributos y campos.

        Elemento de la tabla DynamoDB en el editor de elementos.

      • Pulsa en el botón Vista JSON que está en la parte superior derecha para ver la entrada en formato JSON.

      • En la vista JSON activa/desactiva el conmutador para cambiar entre el formato JSON normal y el de DynamoDB. Comprueba las diferencias.

        Ejemplo

        Por ejemplo, la entrada en JSON

        {
 "sample_time": 1721983656138,
 "device_id": 1,
 "device_data": {
   "door": false,
   "temperature": 21.82
 }
}

        se vería en el formato JSON del DynamoDB como

        {
 "sample_time": {
  "N": "1721983656138"
 },
 "device_id": {
  "N": "1"
 },
 "device_data": {
  "M": {
   "door": {
    "BOOL": false
   },
   "temperature": {
    "N": "21.82"
   }
  }
 }
}

        donde como puede verse, cada valor es precedido de una clave que indica su tipo.

    4. Para finalizar la prueba pulsa Ctrl+C en el terminal de la instancia VSCode en el que esté ejecutándose el script start.sh.

    Justificación de la actividad

    Toma las siguientes capturas para la memoria de justificación de la práctica:

    1. En la consola del DynamoDB las propiedades de la tabla trucks-data.
    2. En la consola IoT las propiedades de la regla truck2ddb y los detalles de la acción DynamoDB.
    3. Instancia VSCode en la que se vea la salida del terminal en el que se ejecutó el script start.sh.
    4. En la consola del DynamoDB, el explorador de elementos en el que se vean las entradas añadidas a la tabla trucks-data.

    Importante

    Las capturas tienen que parecerse a las que se tomaron en el curso y en la práctica 1. Las capturas tomadas en la consola AWS tienen que incluir el menú superior en el que pueda verse el nombre de usuario de la cuenta.
