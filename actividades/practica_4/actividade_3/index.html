    Actividade 3

    COMPOÑENTES PERSONALIZADOS DE APRENDIZAXE MÁQUINA

    Aviso

    Para poder realizar esta actividade é obrigatorio realizar previamente a actividade 2.

    Obxectivo

    O obxectivo desta actividade é crear un compoñente personalizado para a execución de modelos de aprendizaxe máquina (ML). A partir do compoñente de inferencia da actividade anterior (aws.greengrass.DLRImageClassification) vamos crear unha versión modificada que se subscriba a un tópico IPC predefinido no que agarde recibir mensaxes JSON co seguinte esquema: 

    {
    "image": "<ficheiro_jpeg>"
}
    Cada vez que reciba unha mensaxe no tópico IPC, o compoñente accederá no directorio predefinido á imaxe indicada na mensaxe, fará unha inferencia con ela e publicará o resultado da inferencia no tópico MQTT predefinido.

    Nota

    Podes ver aquí a documentación sobre a implementación de compoñentes ML personalizados.

    Importante

    Nesta actividade úsase a CLI de AWS. Para que funcione correctamente tes que ter configuradas as túas credenciais con aws configure (mira na sección 2 do enunciado da práctica como facelo se non te lembras).

    Creación do compoñente de inferencia ML personalizado

    Para crear o compoñente fai o seguinte na instancia VSCode:

    1. Descarga a receita do compoñente proporcionado por AWS no directorio de receitas.

      Nota

      Os seguintes comandos descargan a receita desde o servizo Greengrass usando a CLI de AWS.

      $ cd ~/environment/GreengrassCore/recipes
$ DLR_INFERENCE_ARN=$(aws greengrassv2 list-components \
    --scope PUBLIC \
    --query 'components[?componentName==`aws.greengrass.DLRImageClassification`]' | jq -r '.[0].arn')
$ DLR_INFERENCE_VERSION_ARN=$(aws greengrassv2 list-component-versions \
    --arn $DLR_INFERENCE_ARN \
    --query 'componentVersions[0].arn' \
    --output text)
$ DLR_INFERENCE_VERSION=$(echo $DLR_INFERENCE_VERSION_ARN | awk -F: '{print $NF}')
$ aws greengrassv2 get-component \
    --arn $DLR_INFERENCE_VERSION_ARN \
    --recipe-output-format JSON \
    --query recipe \
    --output text | base64 --decode | jq '.' > aws.greengrass.DLRImageClassification-$DLR_INFERENCE_VERSION.json

      Descarga da receita do compoñente de AWS.

    2. Descarga a receita modificada que vamos usar para o compoñente personalizado. 

      $ wget -O com.example.CustomDLRImageClassification-1.0.0.json https://miot-cniot.github.io/actividades/practica_4/stuff/CustomDLRImageClassification-1.0.0.json

      Importante

      Edita a receita e insire o teu nome no campo ComponentPublisher.

      Descarga da receita modificada.

    3. Compara as receitas e comproba os cambios que se fixeron para adaptala ao noso exemplo. Os principais foron:

      • Reduciuse o número de plataformas soportadas polo compoñente á única que nos interesa para o exemplo.
      • Engadironse á configuración unha política de control de acceso para os tópicos IPC e un parámetro LocalTopic para configurar o tópico IPC a usar.

    4. Comproba os artefactos do compoñente proporcionado por AWS que están instalados na instancia VSCode. 

      $ sudo ls -l /greengrass/v2/packages/artifacts-unarchived/aws.greengrass.DLRImageClassification/$DLR_INFERENCE_VERSION/image_classification/

      Artefactos do compoñente DLRImageClassification.

    5. Crea o directorio para os artefactos do compoñente personalizado. 

      $ mkdir -p ~/environment/GreengrassCore/artifacts/com.example.CustomDLRImageClassification/1.0.0 && cd ~/environment/GreengrassCore/artifacts/com.example.CustomDLRImageClassification/1.0.0

    6. Copia os ficheiros Python do compoñente proporcionado por AWS ao directorio de artefactos do compoñente personalizado e configura os permisos. 

      $ sudo cp /greengrass/v2/packages/artifacts-unarchived/aws.greengrass.DLRImageClassification/$DLR_INFERENCE_VERSION/image_classification/*.py .
$ sudo chown ubuntu:ubuntu *.py
$ chmod 664 *.py

      Artefactos do compoñente personalizado.

    7. Descarga o ficheiro inference.py modificado para o compoñente personalizado. 

      $ mv inference.py inference.1.py
$ wget https://miot-cniot.github.io/actividades/practica_4/stuff/inference.py

      Ficheiros inference do compoñente personalizado.

    8. Abre ambos ficheiros inference e comproba os cambios que se fixeron para adaptalo ao noso exemplo. Os principais foron:

      • Engadiuse o código que realiza a subscrición ao tópico IPC.
      • Definiuse un handler (InferenceRequestHandler) para procesar os eventos da subscrición IPC. A parte máis relevante do handler é o método on_stream_event que é o que procesa as mensaxes que se reciben no tópico e fai unha inferencia se procede.

      Nota

      Presta atención a que o código engadido en inference.py é semellante ao do Subscriber que se viu na sección 5 do curso.

    9. Unha vez remates de comprobar as diferenzas, elimina a copia inference.1.py.

    10. Crea un directorio para as imaxes e descarga a imaxe de proba. 

      $ mkdir ~/environment/image_classification && cd ~/environment/image_classification
$ wget https://raw.githubusercontent.com/awslabs/aws-greengrass-labs-ml-components/main/dlr/aws.greengrass.DLRImageClassification/image_classification/sample_images/cat.jpeg

      Contido do directorio de imaxes.

    Despregadura do compoñente

    1. Comproba que ningún dos compoñentes despregados na instancia estexa en estado BROKEN. Se houbera algún compoñente local (non despregado desde AWS IoT) en estado BROKEN, podes reinicialo ou eliminalo. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep BROKEN -B 2 -A 1

    2. Na consola do AWS IoT fai unha nova despregadura no dispositivo Greengrass edgeDevice que só conteña o compoñente aws.greengrass.Cli.

    3. Asegúrate de que a despregadura rematou correctamente e que a única dependencia do compoñente aws.greengrass.DLRImageClassification que queda no dispositivo é a despregadura local do runtime de DLR. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3

      Resultado da comprobación.

    4. Comproba de novo que non haxa ningún compoñente na instancia en estado BROKEN despois da despregadura.

    5. No cliente MQTT da consola de AWS IoT subscríbete ao tópico ml/custom/image-classification, no que o compoñente personalizado publicará os resultados das inferencias.

    6. Desprega o compoñente de inferencia ML personalizado. 

      $ sudo /greengrass/v2/bin/greengrass-cli deployment create \
    --recipeDir ~/environment/GreengrassCore/recipes \
    --artifactDir ~/environment/GreengrassCore/artifacts \
    --merge "com.example.CustomDLRImageClassification=1.0.0"

    7. Comproba que a despregadura rematou correctamente. 

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3  
$ sudo tail -5 /greengrass/v2/logs/com.example.CustomDLRImageClassification.log

      Resultado da comprobación.

    8. Comproba tamén se se recibiu no cliente MQTT da consola AWS IoT o resultado da inferencia no tópico ml/custom/image-classification.

      Mensaxe recibida no tópico MQTT.

    Nota

    Se os pasos 7 ou 8 non dan os resultados agardados, comproba no log do Greengrass se houbo erros durante a despregadura do compoñente. Podes consultar aquí os erros máis comúns.

    Verificación do funcionamento

    1. Abre un novo terminal na instancia VSCode e subscríbite ao tópico IPC ml/image. Mantén este terminal aberto. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub sub -t="ml/image"
Successfully subscribed to topic: ml/image

    2. Desde outro terminal diferente publica unha mensaxe no tópico ml/image. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub pub -m="{\"image\": \"cat.jpeg\"}" -t="ml/image"

      Mensaxe publicada no tópico IPC.

      Nota

      No terminal no que executaches a subscrición aparecerá a mensaxe {"image": "cat.jpeg"} que ten o formato JSON que o compoñente agarda recibir e o nome da imaxe coa que se realiza a inferencia.

    3. Comproba que no cliente MQTT da consola AWS IoT se recibira no tópico ml/custom/image-classificationunha segunda mensaxe co resultado da inferencia.

    4. Descarga outra imaxe no directorio de imaxes. 

      $ cd ~/environment/image_classification
$ wget -O cat2.jpeg https://www.publicdomainpictures.net/pictures/90000/velka/cat-14022476612Gk.jpg

      Contido do directorio de imaxes.

      Nota

      Podes ver aquí a imaxe descargada.

    5. Publica a mensaxe co nome do novo ficheiro e comproba que se reciba no cliente MQTT o resultado da inferencia. 

      $ sudo /greengrass/v2/bin/greengrass-cli pubsub pub -m="{\"image\": \"cat2.jpeg\"}" -t="ml/image"

      Mensaxe co resultado da inferencia.

    6. Se queres podes facer máis probas descargando outras imaxes e publicando o seu nome.

    Publicación e despregadura do compoñente

    Vamos agora a publicar o compoñente para poder despregalo desde AWS IoT. Fai o seguinte:

    1. Crea un bucket S3 para subir os artefactos e a receita do compoñente. 

      $ AWS_DEFAULT_REGION=us-east-1 && \
    EPOCH_TIME=$(date +"%s") && \
    S3_BUCKET=ggcv2-workshop-$HOSTNAME-$EPOCH_TIME && \
    aws s3 mb s3://$S3_BUCKET --region $AWS_DEFAULT_REGION
make_bucket: ggcv2-workshop-ip-172-31-80-21-1761214805

    2. Edita a receita do compoñente com.example.CustomDLRImageClassification e troca o manifesto polo seguinte.

      Manifests
      "Manifests": [
    {
      "Platform": {
        "os": "linux",
        "architecture": "amd64"
      },
      "Lifecycle": {
        "setEnv": {
          "DLR_IC_MODEL_DIR": "{variant.DLR.ImageClassification.ModelStore:artifacts:decompressedPath}/{configuration:/ModelResourceKey/x86_64}",
          "DEFAULT_DLR_IC_IMAGE_DIR": "/home/ubuntu/environment/image_classification/",
          "TOPIC": "{configuration:/LocalTopic}"
        },
        "run": {
          "RequiresPrivilege": "true",
          "script": "\n                                    export PATH=\"{variant.DLR:configuration:/MLRootPath}/greengrass_ml_dlr_conda/bin:$PATH\"\n                                    eval \"$({variant.DLR:configuration:/MLRootPath}/greengrass_ml_dlr_conda/bin/conda shell.bash hook)\"\n                                    conda activate greengrass_ml_dlr_conda\n                                    python3 {artifacts:decompressedPath}/custom/inference.py"
        }
      },
     "Artifacts": [
        {
           "URI": "s3://[O_NOME_DO_TEU_BUCKET]/artifacts/com.example.CustomDLRImageClassification/1.0.0/custom.zip",
           "Unarchive": "ZIP"
        }
     ]
    }
],

      Os cambios que se fixeron foron:

      • Engadiuse o obxecto Artifacts para descargar os artefactos de S3.

        Importante

        Lembra editar na URI o nome do teu bucket.

      • No script cambiouse a localización do ficheiro inference.py de {artifacts:path} a {artifacts:decompressedPath}/custom para usar a ruta na que Greengrass descomprime o ficheiro descargado de S3.

    3. Comprime os artefactos do compoñente e sube o ficheiro comprimido e a receita ao bucket S3. 

      $ sudo apt install zip
$ cd ~/environment/GreengrassCore
$ ARTIFACTS_DIR="./artifacts/com.example.CustomDLRImageClassification/1.0.0"
$ zip -j $ARTIFACTS_DIR/custom.zip $ARTIFACTS_DIR/*.py
$ aws s3 cp $ARTIFACTS_DIR/custom.zip s3://$S3_BUCKET/artifacts/com.example.CustomDLRImageClassification/1.0.0/
$ aws s3 cp ./recipes/com.example.CustomDLRImageClassification-1.0.0.json s3://$S3_BUCKET/recipes/

      Suba a S3 dos artefactos e a receita.

    4. Comproba que os contidos do bucket S3 son correctos. 

      $ aws s3 ls --recursive s3://$S3_BUCKET

      Resultado da comprobación.

    5. Crea o compoñente no AWS IoT Core. 

      $ cd ~/environment/GreengrassCore/recipes
$ aws greengrassv2 create-component-version --inline-recipe fileb://com.example.CustomDLRImageClassification-1.0.0.json --region $AWS_DEFAULT_REGION

      Resultado da creación do compoñente.

    6. Comproba que aparece na listaxe de compoñentes. Compróbao tamén na consola do AWS IoT. 

      $ aws greengrassv2 list-components --region $AWS_DEFAULT_REGION --query='components[?componentName==`com.example.CustomDLRImageClassification`]'

      Resultado da comprobación na instancia VSCode.

      Resultado da comprobación no AWS IoT.

    7. Elimina o compoñente despregado localmente. Asegúrate de que a única dependencia do compoñente que queda no dispositivo é a despregadura local do runtime de DLR. 

      $ sudo /greengrass/v2/bin/greengrass-cli --ggcRootPath /greengrass/v2 deployment create --remove "com.example.CustomDLRImageClassification"  
$ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3

      Resultado da eliminación do compoñente.

    8. Asegúrate de que non haxa ningún compoñente na instancia en estado BROKEN.

    9. Na consola do AWS IoT fai unha nova despregadura no dispositivo Greengrass edgeDevice que conteña só os compoñentes aws.greengrass.Cli e com.example.CustomDLRImageClassification.

      Compoñente personalizado despregado desde AWS IoT.

    10. Comproba na consola do AWS IoT e na instancia que a despregadura remate correctamente.

      Resultado da comprobación na instancia VSCode.

    11. Verifica o funcionamento correcto do compoñente repetindo os pasos da sección de verificación.

    Xustificación da actividade

    Toma as seguintes capturas para a memoria de xustificación da práctica:

    1. Consola do AWS IoT mostrando as propiedades da última despregadura no dispositivo edgeDevice coa aba Compoñentes escollida, de modo que poida verse que o compoñente com.example.CustomDLRImageClassification foi despregado.

    2. Instancia VSCode na que poidan verse na árbore de directorios os artefactos e receita do compoñente com.example.CustomDLRImageClassification e os contidos do directorio image_classification, e ademais:

      • A saída do terminal no que se executou o comando de subscrición ao tópico ml/image.
      • A saída do terminal desde o que se publicaron as mensaxes no tópico ml/image.
      • A saída da execución dos comandos:
      $ aws s3 ls --recursive s3://$S3_BUCKET
$ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3
$ sudo tail -3 /greengrass/v2/logs/com.example.CustomDLRImageClassification.log

      Nota

      O último comando ten que executarse despois de completar unha inferencia e ten que mostrar as mensaxes do log que indican que se enviaron os resultados da inferencia ao AWS IoT Core (se é preciso modifica a cantidade de liñas mostradas).

      Exemplo

    3. Consola do AWS IoT coa mensaxe MQTT recibida no tópico ml/custom/image-classification para o ficheiro cat2.jpeg, na que poida verse o payload.

      Nota

      A mensaxe ten que ser dunha inferencia realizada polo compoñente despregado desde AWS IoT, é dicir, non vale a mensaxe do paso 5 da sección de verificación que se fai por primeira vez co compoñente despregado localmente.

    Importante

    As capturas teñen que asemellarse ás que se tomaron no curso e nas prácticas anteriores. As capturas tomadas na consola AWS teñen que incluír o menú superior no que poida verse o nome de usuario da conta.
