    Actividade 2

    COMPOÑENTES DE APRENDIZAXE MÁQUINA

    Obxectivo

    O obxectivo desta actividade é comprobar o funcionamento dos compoñentes para a execución de modelos de aprendizaxe máquina en dispositivos Greengrass. Usaremos como exemplo o compoñente de clasificación de imaxes con Deep Learning Runtime (DLR).

    Nota

    Podes ver aquí a documentación sobre a execución de modelos de Aprendizaxe Máquina no Greengrass.

    Preparación da instancia VSCode

    Antes de despregar o compoñente, temos que aumentar a cantidade de disco dispoñíbel na instancia VSCode. Fai o seguinte:

    1. Nun terminal da instancia VSCode executa o comando df -h para ver o espazo de disco dispoñíbel.

      Espazo de disco dispoñíbel.

    2. Na consola do CloudFormation, na aba Recursos da pila edgeDevice preme no identificador do recurso EC2Instance. Abrirase a consola do EC2 mostrando a instancia edgeDevice.

    3. Na consola EC2 escolle a instancia edgeDevice para ver as súas propiedades e na aba Almacenamento preme no identificador do volume EBS da instancia. Abrirase a consola de volumes EBS mostrando o volume.

    4. Escolle o volume e no menú de Accións escolle a opción Crear instantanea (snapshot). Pon unha descrición e acepta para crear a instantanea.

      Nota

      Esta instantanea serviranos como copia de respaldo no caso de que haxa algún problema durante o redimensionamento do volume.

      Creación da instantanea do volume.

    5. Unha vez creada a instantanea, escolle de novo o volume na consola de volumes EBS e no menú de Accións escolle a opción Modificar volume. Cambia o tamaño a 100GiB e acepta para modificar.

      Modificación do tamaño do volume.

    6. Para poder facer uso do novo espazo adicional hai que agardar a que o volume pase ao estado En uso - optimizando (#%). Unha vez que iso aconteza fai o seguinte nun terminal da instancia VSCode:

      • Executa o comando lsblk /dev/nvme0n1. O volume aparece co novo tamaño porén o espazo adicional aínda está sen asignar a ningunha partición.

        Espazo de disco adicional aínda sen usar.

      • Incrementa o tamaño da partición 1 executando o comando:

        sudo growpart /dev/nvme0n1 1

      • Executa de novo o comando lsblk /dev/nvme0n1 e comproba como agora o espazo adicional aparece xa asignado á partición 1.

        Espazo adicional asignado á partición 1.

      • Redimensiona o sistema de ficheiros montado nesa partición executando o comando: 

        sudo resize2fs /dev/root`

      • Comproba que se redimensionou o sistema de ficheiros executando o comando df -h.

        Sistema de ficheiros redimensionado.

    Despregadura do compoñente de clasificación de imaxes

    O compoñente de clasificación de imaxes con DLR define dependencias co runtime de DLR e cun modelo ResNet-50 pre-adestrado para realizar a clasificación de imaxes.

    Aínda que ao despregar o compoñente as súas dependencias instálanse automaticamente no dispositivo destino, debido a un bug no compoñente do runtime de DLR proporcionado por AWS, non se completa a creación dun ambiente Conda que é necesario para o correcto funcionamento do compoñente de clasificación de imaxes.

    Debido a isto, precisaremos facer un paso previo no que despregaremos unha versión local do compoñente do runtime de DLR co bug corrixido.

    Despregadura local do runtime DLR

    Para realizar a despregadura local do compoñente do runtime de DLR fai o seguinte:

    1. Clona o repositorio do compoñente no directorio environment da instancia VSCode.

      Nota

      Os seguintes comandos clonan unicamente a parte do repositorio de compoñentes ML de AWS que corresponde ao compoñente variant.DLR.

      $ cd ~/environment
$ git clone --depth=1 --no-checkout https://github.com/awslabs/aws-greengrass-labs-ml-components.git
$ cd aws-greengrass-labs-ml-components/
$ git sparse-checkout set --no-cone dlr/variant.DLR
$ git checkout main

      Contidos do directorio no que se clonou o repositorio do compoñente.

    2. Crea un directorio para os artefactos do compoñente local e copia nel os artefactos do compoñente clonado.

      $ mkdir ~/environment/GreengrassCore/artifacts/variant.DLR/1.6.16
$ cp ~/environment/aws-greengrass-labs-ml-components/dlr/variant.DLR/environment.yaml ~/environment/GreengrassCore/artifacts/variant.DLR//1.6.16/
$ cp -R ~/environment/aws-greengrass-labs-ml-components/dlr/variant.DLR/installer ~/environment/GreengrassCore/artifacts/variant.DLR/1.6.16/installer

    3. Crea un directorio para a receita do compoñente local e copia nel a receita do compoñente clonado.

      $ cp ~/environment/aws-greengrass-labs-ml-components/dlr/variant.DLR/recipe.json ~/environment/GreengrassCore/recipes/variant.DLR-1.6.16.json

    4. Edita a receita e modifica o seguinte:

      • ComponentVersion: 1.6.16
      • VersionRequirement: >=2.0.0 <3.0.0

      • Manifests: trócao polo contido seguinte:

        Manifests
        "Manifests": [
    {
        "Platform": {
            "os": "linux",
            "architecture": "amd64"
        },
        "Lifecycle": {
            "install": {
                "RequiresPrivilege": "true",
                "Setenv": {
                    "LANGUAGE": "en_US.UTF-8",
                    "LC_ALL": "en_US.UTF-8",
                    "LANG": "en_US.UTF-8",
                    "CONDA_PLUGINS_AUTO_ACCEPT_TOS": "true"
                },
                "script": "\nbash {artifacts:path}/installer/installer.sh -p {configuration:/MLRootPath} -e {artifacts:path}/environment.yaml -i {configuration:/UseInstaller}",
                "timeout": "900"
            }
        }
    }
],

        Nota

        Se comparas o Manifests da receita modificada coa orixinal verás que o único que fixemos foi eliminar as plataformas que non nos interesan e, para a plataforma Linux con arquitectura amd64 (a da instancia Ubuntu que usamos como edgeDevice), fixemos os cambios precisos para usar os artefactos locais en lugar dos descargados de S3 e engadimos unha variábel de ambiente para aceptar os TOS de Conda desde o script de instalación en modo non interactivo (que é a causa do bug que queremos evitar).

      Artefactos e receita modificada do compoñente.

    5. Comproba que ningún dos compoñentes despregados na instancia estexa en estado BROKEN executando o comando:

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep BROKEN -B 2 -A 1

      Nota

      Se algún dos compoñentes locais (non despregados desde AWS IoT) está en estado BROKEN, podes reinicialo ou eliminalo se reinicialo non o soluciona. Mira no apartado Operation check of sample component da sección Tips&Troubleshoot do curso como facelo.

    6. Desprega o compoñente local do runtime de DLR.

      $ sudo /greengrass/v2/bin/greengrass-cli deployment create \
    --recipeDir ~/environment/GreengrassCore/recipes  \
    --artifactDir ~/environment/GreengrassCore/artifacts \
    --merge "variant.DLR=1.6.16"

    7. Verifica que a despregadura foi correcta executando os seguintes comandos.

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep DLR -A 3 -m 1
$ sudo /greengrass/v2/work/variant.DLR/greengrass_ml/greengrass_ml_dlr_conda/bin/conda tos
$ sudo /greengrass/v2/work/variant.DLR/greengrass_ml/greengrass_ml_dlr_conda/bin/conda info --envs

      Resultado do primeiro comando: compoñente despregado correctamente.

      Resultado do segundo comando: TOS de Conda aceptados.

      Resultado do terceiro comando: ambiente de Conda para ML creado.

    Despregadura do compoñente de clasificación de imaxes

    Unha vez que temos unha despregadura local do runtime de DLR no dispositivo Greengrass, xa podemos despregar o compoñente de clasificación de imaxes:

    1. Comproba de novo que ningún dos compoñentes despregados na instancia estexa en estado BROKEN despois de despregar o runtime de DLR executando o comando:

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep BROKEN -B 2 -A 1

    2. Instala na instancia a libraría GNU C, que é un dos requisitos do compoñente de clasificación de imaxes.

      $ sudo apt update
$ sudo apt install glibc-source -y

    3. No cliente MQTT da consola de AWS IoT subscríbete ao tópico predefinido ml/dlr/image-classification. Este é o tópico MQTT no que o compoñente publica o resultado da clasificación.

      Nota

      O tópico MQTT é unha das opcións que pode cambiarse na configuración do compoñente.

    4. Abre outra consola de AWS IoT nunha xanela diferente do teu navegador e escolle a opción Compoñentes dentro do menú Dispositivos Greengrass.

    5. Escolle a aba Compoñentes públicos e preme no nome do compoñente aws.greengrass.DLRImageClassification.

    6. Revisa a configuración por defecto e comproba na documentación do compoñente o significado dos parámetros configurados. Revisa tamén as dependencias do compoñente.

    7. Desprega o compoñente premendo en Despregar (Implantar) e indica as opcións seguintes:

      • Adicionar á despregadura: escolle Adicionar a unha despregadura existente e marca a despregadura Deployment for GreengrassQuickStartGroup. Preme no botón Seguinte para ir ao asistente da despregadura.

      • No paso 2 do asistente (Seleccionar compoñentes) desactiva todos os compoñentes excepto aws.greengrass.DLRImageClassification e aws.greengrass.Cli.

        Nota

        Nos demais pasos do asistente deixa todas as opcións nos seus valores por defecto.

    Verificación da despregadura

    Nota

    Se algún dos pasos de verificación non da o resultado agardado, comproba nos logs do Greengrass (/greengrass/v2/logs/greengrass.log) e do compoñente (/greengrass/v2/logs/aws.greengrass.DLRImageClassification.log) se houbo erros durante a despregadura do compoñente. Podes consultar aquí os erros máis comúns.

    1. Na consola IoT comproba que a despregadura remata sen erros.

    2. No cliente MQTT da consola do AWS IoT comproba que se recibiu o resultado da inferencia no tópico ml/dlr/image-classification.

      Resultado do algoritmo de clasificación no tópico MQTT.

      Nota

      Podes ver aquí a imaxe que se usa por defecto para realizar a inferencia. Nunha situación real a imaxe podería ser unha captura tomada mediante unha camara conectada ao dispositivo Greengrass.

    3. Comproba a saída no ficheiro de log do compoñente. 

      $ sudo tail -2 /greengrass/v2/logs/aws.greengrass.DLRImageClassification.log

      Resultado do algoritmo de clasificación no log do compoñente.

      $ sudo /greengrass/v2/bin/greengrass-cli component list | grep -E 'Component Name:.*DLR' -A 3
$ sudo tail -2 /greengrass/v2/logs/aws.greengrass.DLRImageClassification.log

      Exemplo

    2. Consola IoT coa mensaxe MQTT recibida no tópico ml/dlr/image-classification, na que poida verse o payload.

    As capturas teñen que asemellarse ás que se tomaron no curso e nas prácticas anteriores. As capturas tomadas na consola AWS teñen que incluír o menú superior no que poida verse o nome de usuario da conta.
