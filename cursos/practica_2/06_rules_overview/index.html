    6. Introdución ás regras IoT

    O problema da acumulación de datos

    Acumular cada bit de datos dun sensor significa que terás unha gran cantidade de datos recibidos. Imaxina o noso escenario coa nosa frota de camións de xeados con 10 camións, cada un con cinco sensores. Se cada sensor publica, por exemplo, tres tipos de datos (marca temporal, temperatura ou estado da porta e estado do sensor) cada 15 segundos, isto representa 60 medicións cada minuto para cada camión, é dicir, 600 medicións cada minuto.

    A minería de datos destes datos mediante os servizos de análise de AWS pode proporcionar información sobre o funcionamento da frota. Estes servizos axudan na supervisión operativa, que é máis unha opción reactiva, atrasada no tempo.

    Pero para unha operación diaria, cunha supervisión case en tempo real, pode haber elementos específicos dos que se queira estar ao tanto a medida que acontecen, para mitigar unha situación ou tomar unha decisión empresarial adecuada apoiada polos datos.

    Imaxina unha caída súbita da temperatura no conxelador dun camión. Ter unha notificación directa deste evento específico sería útil para o condutor. Porén, a revisión dos datos agregados almacenados no DataWarehouse da compañía só mostraría, p.ex., a temperatura media mensual, o que non sería útil cando un camión sofre unha caída de temperatura repentina.

    Antes de explicar como se solucionaría esta situación, imos ver mediante un exemplo o problema da acumulación de datos por subscrición.

    Introdución ás regras

    Como xestionar este diluvio de datos para recibir ou aillar só aqueles que nos interesan? É posíbel que queiras xestionar dalgunha maneira a gran cantidade de datos recibidos que non son úteis para os teus obxectivos comerciais diarios. Algúns datos son necesarios no momento e outros poderían precisarse máis tarde para realizar unha análise a longo prazo. O que procuras é unha forma de xestionar a gran cantidade de datos recollidos e filtrar ou dirixir os datos a diferentes destinos na nube.

    A xestión dos datos IoT comeza coa aplicación de regras do AWS IoT. Estas regras son un dos principais métodos para filtrar e dirixir a comunicación desde AWS IoT Core a outros servizos de AWS.

    Ao usar regras, os teus dispositivos poden interactuar cos servizos de AWS. Cando os datos entran no AWS IoT Core, as regras son avaliadas e as accións aplicadas sobre os fluxos de datos dos tópicos MQTT. Podes usar regras para realizar diferentes tarefas, como as seguintes:

    • Escribir datos dun dispositivo nunha táboa de Amazon DynamoDB.
    • Invocar unha función de AWS Lambda para extraer ou transformar datos específicos.
    • Gardar un ficheiro ou un conxunto de datos en Amazon S3.

    Nota

    Para que AWS IoT poida realizar estas accións, debes concederlle o rol e os permisos de AWS Identity and Access Management (IAM) axeitados para que poida actuar no teu nome.

    Anatomía dunha regra

    As regras teñen como mínimo o seguinte:

    • Un nome
    • Unha declaración de consulta
    • Unha ou máis accións a realizar

    Tamén podes ter información adicional, como a seguinte:

    • Unha descrición
    • Unha acción que se realiza en caso de erro
    • Etiquetas

    Linguaxe de consulta

    As declaracións de consulta das regras do AWS IoT están escritas cunha sintaxe similar á linguaxe de consulta estruturada (SQL) utilizada no mundo das bases de datos. A consola de AWS IoT presenta un ambiente de desenvolvemento estruturado para crear declaracións de consulta para filtrar e enrutar mensaxes MQTT.

    A consulta de regra que se mostra no seguinte exemplo está a seleccionar todas as mensaxes enviadas por todos os sensores da carga principal no camión_1 que informen unha temperatura (informada como temp) superior a 37. Esta consulta actúa como un filtro para ignorar as mensaxes que non coincidan cos criterios.

    Hai diferentes accións dispoñíbeis. Por exemplo, almacenar as mensaxes seleccionadas nun bucket de Amazon S3, ou enviar unha notificación (publicar) a través do Amazon Simple Notification Service (Amazon SNS) como se mostra na seguinte imaxe, e moitas máis. Ao crear a acción, especifícase un rol de IAM que conceda a AWS IoT permiso para publicar no tema de SNS.

    Nota

    É posíbel asociar varias accións a unha única regra. Nese caso, as mesmas mensaxes filtradas pola regra envíanse a varios destinos.

    Redución dos custos de mensaxería

    Cando hai que enviar mensaxes a grande escala, na orde de decenas de miles ou máis nun curto período de tempo, pódese usar a función de inxestión básica (Basic Ingest) para reducir os custos de mensaxería.

    Coa inxestión básica, podes enviar de forma segura datos desde os teus dispositivos ou aplicacións aos servizos de AWS compatíbeis coas accións de regras de AWS IoT sen incorrer en custos de mensaxería. A inxestión básica optimiza o fluxo de datos eliminando o Message Broker da ruta de inxestión, o que o fai máis rendíbel.

    As mensaxes do Basic Ingest teñen nomes de tópico que comezan con $aws/rules/rule_name para os seus tres primeiros niveis, onde rule_name é o nome da regra de AWS IoT que queres invocar. Poden usarse as regras existentes con Basic Ingest engadíndolles o prefixo ($aws/rules/rule_name) ao tópico da mensaxe que normalmente se usaria para invocar as regras.

    Por exemplo, se tes unha regra chamada BuildingManager que se invoca mediante mensaxes con tópicos como Buildings/Building5/Floor2/Room201/Lights ("sql": "SELECT * FROM 'Buildings/#'"), podes invocar a mesma regra con Basic Ingest enviando unha mensaxe ao tópico $aws/rules/BuildingManager/Buildings/Building5/Floor2/Room201/Lights.

    Para obter máis información sobre Basic Ingest podes consultar: Reducir os custos de mensaxería con Basic Ingest.
