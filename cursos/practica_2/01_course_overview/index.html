    1. Introdución

    Escenario

    Neste titorial, faremos referencia a un escenario típico para o uso de dispositivos IoT nun contexto comercial. Unha empresa de servizos de alimentación con sede na Piadela (Betanzos), transporta xeados a supermercados en toda a área metropolitana da Coruña. Un dos maiores retos no proceso de distribución é manter a cadea de frío. Nos últimos meses, a empresa detecto unha deterioración do 30 por cento mentres os produtos están en tránsito.

    O problema podería ser causado polas unidades de refrixeración do camión que se apagan, as altas temperaturas do verán, as portas dos camións que se deixan abertas, problemas eléctricos ou algo no que aínda non se pensou. A compañía decidiu que necesitaba recoller datos dos seus camións para investigar a situación.

    A compañía quere usar AWS IoT Core para monitorizar varios aspectos do funcionamento do camión e determinar as causas exactas da deterioración.

    Usando os seguintes sensores a bordo, recóllense datos específicos:

    • O estado da porta do conxelador cun interruptor de E/S dixital que indica canto tempo está aberta a porta.
    • O sensor interno de temperatura recolle as flutuacións na temperatura do conxelador.
    • O medidor da tensión que vai ao conxelador mide se a subministración elétrica do conxelador é regular.
    • O rexistro da data e hora asociada ás outras medicións permite cruzar eventos con patróns meteorolóxicos e controladores específicos.

    Estes sensores que recollen os datos representan dispositivos. A recollida dos datos que proporcionan de forma remota chámase telemetría, da que falaremos en detalle máis adiante neste titorial.

    Creación de intelixencia a partir destes datos

    Para xestionar este tipo de escenarios, terás que aprender sobre telemetría: como os datos recollidos polos dispositivos son enviados e usados na nube de AWS. Por exemplo, os sensores do camión de xeados poderían enviar lecturas de temperatura, peso e movemento ao AWS IoT Core para a súa análise e procesamento.

    Para usar mellor os dispositivos IoT, terás que comprender como un protocolo específico, o Message Queuing Telemetry Transport (MQTT), axuda á comunicación entre o AWS IoT Core e os dispositivos. Esta comunicación realízase mediante un concepto denominado modelo de publicación-subscrición.

    Tamén terás que coñecer como os dispositivos poden inxectar datos noutros servizos da AWS. En función dos datos de telemetría, é posíbel que haxa que enviar unha notificación a un móbil ou almacenar un valor nun bucket do servizo S3 (Simple Storage Service) de AWS. As regras do AWS IoT Core determinan como as mensaxes son encamiñadas a outros servizos AWS. Para obter máis información, consulta Regras para AWS IoT.

    Finalmente, terás que entender como funciona a telemetría cando os dispositivos están sen conexión, xa sexa involuntariamente ou por deseño. O camión de xeados no noso escenario probabelmente pasará por áreas con ningunha ou pouca conectividade de rede. AWS IoT Device Shadows é un xeito de aliviar este problema mantendo unha versión do último estado informado do dispositivo IoT independente do estado da conexión.

    Obxectivos

    Ao finalizar este titorial, deberías ser quen de conseguir o seguinte:

    • Explicar como se publican as mensaxes nos tópicos MQTT.
    • Describir a diferenza entre publicar e subscribirse a mensaxes en tópicos MQTT.
    • Explicar como encamiñar datos a outros servizos AWS usando as regras de AWS IoT.
    • Discutir os beneficios de usar Device Shadows para controlar o estado do dispositivo e almacenar o último estado informado.
    • Dar exemplos de como unha solución IoT xestiona o estado dos dispositivos usando sombras de dispositivo.
