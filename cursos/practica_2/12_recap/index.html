    Resumo e Revisión

    Que aprendemos

    Nesta lección, repasamos os conceptos e elementos que comentamos ao longo do curso. Este é un resumo, polo que se algún elemento non está claro ou suscita algunha pregunta, consulte a lección específica e léaa de novo para obter máis detalles dese elemento específico.

    Dispositivos que comunican información

    MQTT

    Os dispositivos IoT usan mensaxes para comunicarse con IoT Core. MQTT é un protocolo que se pode usar para transportar estas mensaxes.

    Publicar-subscribir

    Para consumir estas mensaxes, os dispositivos IoT usan o lado de publicación do modelo de publicación-subscrición para enviar as súas mensaxes a calquera destino (aplicación, servizo de AWS ou outro dispositivo) que se subscriba para recibir estas mensaxes.

    Temas

    Xerarquía de temas

    O que publicas ou ao que te subscribes chámase temas. Os temas axudan a categorizar a información que un dispositivo ou aplicación pode proporcionar nas mensaxes. Unha mensaxe publícase nun tema e un cliente subscríbese a un tema para consumir a mensaxe entrante. Un cliente tamén pode publicar e un dispositivo tamén pode subscribirse a temas.

    Os nomes dos temas están construídos nunha estrutura que se asemella a unha xerarquía de cartafoles e unha boa práctica é definir un nome de tema de xeral a específico, usando barras diagonais (/) para construír eses niveis de xerarquía. Por exemplo, sensor/temperatura/camión_01/conxelador_principal.

    Temas reservados

    AWS IoT Core ten algúns nomes de temas reservados listos para usar. O nome destes temas comeza cun signo de dólar ($).

    Filtros de temas

    Para que os clientes reciban varias mensaxes, como todas as lecturas de temperatura do conxelador principal de todos os camións da flota, pode usar un filtro de temas para subscribirse a varios temas. Os caracteres comodín (# e +) definen un filtro que recibe todas as mensaxes dunha combinación de temas.

    Axente de mensaxes

    IoT Core ofrece un mecanismo para xestionar o tráfico das subscricións de temas. O axente de mensaxes define onde se debe entregar unha mensaxe, en función das subscricións. Por exemplo, enviar unha mensaxe a unha aplicación móbil ou a unha regra que poida chegar a un servizo de AWS como un bucket de S3. As mensaxes pódense entregar a varios destinos se é necesario.

    Regras

    Regras para xestionar o tráfico de mensaxes

    Unha vez que o axente de mensaxes recibe mensaxes dos dispositivos, pode establecer regras para dirixir un subconxunto das mensaxes a outros servizos de AWS nas condicións que defina.

    Anatomía da regra

    Unha regra ten un nome, unha declaración de consulta (usando unha declaración SQL) para seleccionar mensaxes e unha ou máis accións.

    Unha acción define o destino das mensaxes.

    Opción de inxestión básica

    A inxestión básica é unha alternativa para axudar a entregar de forma eficaz grandes volumes de mensaxes desde dispositivos IoT sen incorrer en custos de mensaxes.

    Conectividade

    Lapso na conectividade

    Os dispositivos poden perder a conectividade no campo. Como avalía IoT Core o estado da conexión dos dispositivos? O axente de mensaxes e os dispositivos participan nun escenario de "Podes oírme?".

    pingreq e pingresp

    Os dispositivos envían unha solicitude ao axente de mensaxes. Se hai conectividade, o axente de mensaxes envía unha resposta. Podes personalizar a frecuencia da solicitude-resposta.

    Última vontade e testamento (LWT)

    Se o axente de mensaxes non recibe unha solicitude dun dispositivo, pode definir unha mensaxe LWT que pode enviar cunha mensaxe MQTT estándar nun tema aos clientes. Esta mensaxe publícase ata que se restablece a conectividade.

    Sombras de dispositivos

    Cando se perde a conectividade, o axente de mensaxes ten un conxunto de atributos e valores do dispositivo informados por última vez. Isto chámase sombra de dispositivo. Se o cliente envía unha solicitude de cambio, a sombra toma este cambio como un estado preferido e transmíteo de novo ao dispositivo unha vez que se restablece a conectividade.

    Sombras nomeadas e sen nome

    Podes crear, actualizar ou eliminar unha sombra baixo demanda e asignarlle un nome e referirte a ela a través de subscricións de temas específicos. Podes ter unha única sombra sen nome; ten unha funcionalidade limitada, en comparación cunha sombra nomeada.

    Temas de sombra de dispositivos

    Para xestionar, obter, actualizar, eliminar ou obter o delta dunha sombra, hai temas específicos reservados por IoT Core aos que subscribirse. Estes temas comezan con $aws/things/thingname/shadow/.
