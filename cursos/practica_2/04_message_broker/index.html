    4. Xestión do tráfico de mensaxes: o Message Broker

    Definición do Message Broker

    Na sección anterior, aprendiches que os dispositivos e clientes de IoT poden comunicarse mediante un modelo de publicación-subscrición a tópicos, todo isto usando o protocolo MQTT. A información era bastante xeral para comprender mellor os conceptos. Nesta sección, afondamos un pouco máis en como se produce esta comunicación e os actores implicados, particularmente dentro do AWS IoT Core.

    Un exemplo de broker

    Comecemos de novo cunha analoxía. Observa a seguinte imaxe que resume o escenario.

    Os actores e elementos implicados son os seguintes:

    • Os aspirantes a cineastas

      Imaxina a varias persoas que queren presentar unha idea para unha película a un produtor. Todos teñen unha historia diferente que presentar e queren acceder ao despacho do produtor.

    • A seguranza

      A primeira barreira para acceder é a do garda de seguranza na porta principal.

    • A identificación

      Todo o mundo debe mostrar algunha forma de identificación recoñecida.

    • O mostrador de información

      Unha vez que cada persoa é autenticada, o seguinte paso é o mostrador de información principal no vestíbulo. O propósito da persoa no mostrador non é xulgar o argumento da película, senón dirixir ás persoas ao produtor axeitado.

    • Os produtores

      En función do tipo de película, cada persoa é dirixida ao produtor axeitado. Os produtores tamén poden enviar solicitudes específicas aos aspirantes a cineastas. Produtores que queren guións de documentais, películas de terror, acción ou comedias. O nome do tópico sería algo así como scripts/movies/horror ou scripts/movies/action.

    Neste exemplo, o paso de triaxe no mostrador de información é a clave de toda a operación. Esa persoa realiza o papel de broker, dirixindo o tráfico de aspirantes ao destino correcto para entregar o seu guión. Para recapitular, as compoñentes deste exemplo son as seguintes:

    • Aspirantes a cineastas
    • ID
    • Seguranza
    • Mostrador de información
    • Produtores

    Adecuando o exemplo ao caso IoT

    Como na última sección, imos facer a transición dos distintos compoñentes para adecuar este exemplo ao mundo da IoT.

    Revisa o seguinte diagrama que reflicte os trocos que facemos no exemplo.

    Os actores e elementos no caso IoT son:

    • Os dispositivos IoT

      Trocamos os aspirantes a cineastas por dispositivos e sensores de IoT. En lugar de ter argumentos de películas, temos datos contidos en mensaxes MQTT dispoñíbeis para as entidades que se subscriban aos tópicos publicados.

    • Certificados e credenciais

      Trocamos o ID por un certificado de seguranza e as credenciais necesarias para autenticarse en AWS IoT Core. A comunicación do dispositivo está protexida mediante protocolos de comunicación MQTT ou HTTPS seguros. Estes protocolos usan certificados de cliente X.509 proporcionados por AWS IoT para autenticar as conexións do dispositivo.

    • A pasarela de dispositivos

      Trocamos o porteiro por un compoñente de IoT Core chamado pasarela de dispositivos (Device Gateway). Permite que os dispositivos se comuniquen de forma segura con AWS IoT, reciban execucións de traballos e actualicen o estado de execución do traballo. A pasarela de dispositivos verifica a autenticación dos distintos dispositivos e clientes conectados a ela. É unha das compoñentes de IoT Core responsables da seguranza.

    • O intermediario de mensaxería

      Trocamos o mostrador de triaxe por un intermediario de mensaxería (Message Broker), que xestiona a autorización e a triaxe, entrega as mensaxes publicadas polos dispositivos IoT e entrega unha copia a cada entidade que se subscriba ao tópico. As mensaxes identifícanse mediante un tópico definido pola aplicación. Cando o Message Broker recibe unha mensaxe, volve publicar esa mensaxe nos dispositivos e aplicacións que se subscribiron ao tópico da mensaxe.

    • Os servizos de AWS

      Trocamos os produtores por servizos de AWS ou outros clientes que se subscribiron aos tópicos ofrecidos polos dispositivos IoT.

    Volvendo ao escenario do camión de xeados

    En poucas palabras, o AWS IoT Message Broker é como se comunican os clientes e o AWS IoT Core. Os clientes envían datos publicando unha mensaxe nun tópico. Os clientes reciben mensaxes subscribíndose a un tópico.

    No noso escenario dos xeados, un sensor de temperatura pode publicar unha mensaxe sobre o tópico da temperatura do conxelador principal do camión. A mensaxe retransmítese a IoT Core e é xestionada polo Message Broker.

    O Message Broker é consciente de que hai subscricións para este tópico e mantén unha listaxe de todas as sesións de cliente e as subscricións para cada sesión. Cando se publica unha mensaxe nun tópico, o broker busca sesións con subscricións que se mapean ao tópico. A continuación, o broker reenvía a mensaxe publicada a todas as sesións que teñan un cliente conectado actualmente ou unha sesión persistente.

    Protocolos aceptados

    O Message Broker acepta tres protocolos de comunicación: MQTT 3.1.1 e MQTT 5, MQTT sobre Web Sockets e HTTP 1.1. Tanto MQTT como HTTPS son compatíbeis a través de IPv4 e IPv6.

    A forma de conectarse ao Message Broker depende do protocolo que estea a usar. Os diferentes protocolos requiren diferentes mecanismos de autenticación. Para obter máis información sobre as diferenzas e que autenticación usa cada método, consulta: Protocolos de comunicación de dispositivos.
