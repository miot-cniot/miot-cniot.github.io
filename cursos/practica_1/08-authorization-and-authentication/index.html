    7. Autorización e autenticación de dispositivos IoT

    Ao conectar dispositivos ao IoT Core, a autenticación e a autorización desempeñan diferentes funcións na seguranza dos dispositivos. Como se comentou anteriormente, hai dúas áreas onde se debe aplicar a seguranza nos sistemas IoT:

    • Certificados e políticas de AWS IoT. Utilizados para dispositivos e cousas e as aplicacións que se comunican con eles

    • Roles e políticas de IAM. Utilizados tanto para operadores humanos como para actores software que necesiten interaxir co sistema IoT ou entre si

    Unha visión xeral de como os dispositivos se conectan de forma segura ao AWS IoT Core e de como o AWS IoT Core interactúa con outros servizos.

    Autenticación de dispositivos

    A autenticación é o punto de entrada a AWS IoT Core para os dispositivos. A autenticación é o proceso de verificación da identidade dun cliente ou dun servidor:

    • Autenticación do servidor é o proceso polo cal os dispositivos ou outros clientes se aseguran de que se están a comunicar cun endpoint real de AWS IoT.

    • Autenticación do cliente é o proceso polo cal os dispositivos se autentican co AWS IoT Core.

    Como se comentou anteriormente, os dispositivos e as cousas, e as aplicacións que se comunican con eles, deben autenticarse e deben ser autorizados para realizar as súas funcións (como enviar e recibir mensaxes). Os servidores que xestionan a comunicación e as mensaxes, como pasarelas e brokers, tamén deben ser autenticados e autorizados.

    No proceso de conexión de dispositivos, como o sensor de temperatura no noso escenario, AWS IoT Core crea as credenciais de seguranza requiridas para o dispositivo, que consisten no seguinte:

    • O certificado X.509, que se utiliza para a autenticación do dispositivo.

    • A política de AWS IoT, que se asocia ao certificado e úsase para a autorización do dispositivo, outorgando os permisos necesarios para que o dispositivo realice o seu traballo.

    Certificados X.509

    AWS IoT Core utiliza certificados X.509 para conceder acceso ao servizo aos dispositivos. Despois de que os dispositivos fosen autenticados, as súas operacións e accións permitidas en AWS IoT Core baséanse nunha política de AWS IoT. As operacións inclúen conectarse ao axente de mensaxes, enviar e recibir mensaxes, e obter ou actualizar a sombra de dispositivo dunha cousa.

    Normalmente, os dispositivos de AWS IoT utilizan certificados X.509 para realizar autenticación mutua con AWS IoT. Pódese rexistrar un certificado existente ou deixar que sexa AWS IoT quen xere e rexistre un novo certificado para o dispositivo.

    AWS IoT proporciona autenticación ofrecendo as seguintes opcións:

    • Certificados para autenticación mutua mediante MQTT sobre Transport Layer Security (TLS) v1.2

    • Solicitudes asinadas por Signature Version 4 (SigV4) sobre HTTP

    • MQTT sobre WebSocket, que é similar a outros servizos de AWS

    Tamén poden usarse tokens de autenticación personalizados fornecidos por un servizo de autenticación ou autorización externo. AWS IoT tamén ofrece opcións de autorización flexíbeis e control de acceso granular a través de políticas JSON (JavaScript Object Notation).

    Para obter máis información sobre o uso de certificados para a autenticación, consulta Certificados de cliente X.509.

    Usar certificados dunha CA propia

    Ademais da forma estándar de usar os certificados fornecidos polo AWS IoT Core, os clientes poden utilizar a súa propia autoridade de certificación (CA).

    Unha CA é unha entidade de confianza que emite certificados SSL (Secure Sockets Layer). Estes certificados dixitais son ficheiros de datos utilizados para vincular criptograficamente unha entidade cunha chave pública.

    Un cliente pode usar a súa propia CA se desexa un maior control sobre a validez do certificado e a capacidade de engadir identificadores ao certificado. Este enfoque adoita tomarse cando o cliente ten certificados de cliente asinados por outras autoridades de certificación raíz ou intermedias. Este enfoque maximiza a integración con outros provedores en lugar de usar exclusivamente o AWS Certificate Manager, que é o servizo detrás da creación dos certificados que fornece o AWS IoT Core.

    Autorización de dispositivos

    A autorización é o proceso de concesión de permisos a unha identidade autenticada. Despois de que as identidades sexan autenticadas, aínda non teñen permisos para acceder aos recursos. Para que os dispositivos e os usuarios obteñan permisos, deben ser autorizados para facelo. Isto conséguese mediante o uso de políticas de AWS IoT.

    Políticas de AWS IoT

    Dispositivos, aplicacións móbeis, aplicacións web e aplicacións de escritorio utilizan todas unha identidade autenticada. A identidade só pode executar operacións de AWS IoT se ten unha política que lle conceda permiso. As políticas de AWS IoT asocianse a certificados X.509. A política define o que unha identidade autenticada pode facer e concede os permisos necesarios para que o dispositivo realice o seu traballo.

    As políticas de AWS IoT controlan principalmente o acceso dun recurso ao plano de datos do AWS IoT Core. Cando se envían datos ao AWS IoT Core e se reciben datos del, estase a usar o plano de datos do AWS IoT Core. Isto significa que o plano de datos define se está permitido conectarse ao axente de mensaxes, enviar ou recibir mensaxes MQTT, ou publicar-suscribirse a un tópico específico.

    Nunha sección posterior do titorial explicaranse as políticas de AWS IoT con máis detalle.

    Autorizadores personalizados

    Cando os métodos de autenticación do AWS IoT Core non son suficientes, os clientes poden usar AWS IoT Core para definir autorizadores personalizados que xestionen a autenticación e autorización. Isto é útil cando se precisan mecanismos de autenticación distintos dos que o AWS IoT Core soporta de forma nativa.

    Por exemplo, se se están a migrar dispositivos xa despregados no terreo ao AWS IoT Core e estes dispositivos utilizan un token de portador (bearer token) personalizado ou un nome de usuario e seña MQTT para autenticarse, poden migrarse ao AWS IoT Core sen ter que provisionar novas identidades para eles. Outra razón pola que un cliente podería usar este método sería se o hardware do dispositivo non puidese almacenar os certificados X.509 ou non puidese almacenalos de forma segura.

    Cada autorizador contén unha referencia a unha función Lambda xestionada polo cliente, unha chave pública opcional para validar as credenciais do dispositivo e información de configuración adicional.

    IAM

    Ademais da autenticación e autorización de dispositivos xestionadas polo AWS IoT Core, os roles de IAM traballan con políticas de IAM para conceder ao AWS IoT Core permisos para acceder ao resto de AWS.

    Os usuarios (tanto operadores humanos como actores software) necesitan interaxir co sistema IoT ou entre si. Neste caso, a autenticación e a autorización fornécense mediante políticas de IAM que conceden a unha identidade de IAM, ou recurso de AWS, permisos para acceder a un servizo ou realizar unha función con AWS.

    Os roles e políticas de IAM permiten que AWS IoT acceda a outros recursos de AWS na conta do usuario en representación súa. Por exemplo, se se quere que un dispositivo publique o seu estado nunha táboa de Amazon DynamoDB, os roles de IAM permiten que AWS IoT interactúe co DynamoDB.

    Os actores software (aplicacións móbeis, web ou de escritorio) poden autenticarse con servizos de AWS IoT, a través de usuarios, grupos e roles de IAM e identidades de Amazon Cognito. As aplicacións web e de escritorio utilizan identidades de IAM ou federadas.

    Unha visión xeral dos tres tipos de principais de identidade compatibles con AWS IoT para a autenticación e autorización de dispositivos ou clientes.

    Roles e políticas de IAM

    Os roles de IAM traballan con políticas de IAM para conceder ao AWS IoT Core permisos para acceder ao resto de AWS. As políticas de IAM conceden a unha identidade de IAM, ou recurso de AWS, permisos para acceder a un servizo ou realizar unha función con AWS.

    Por exemplo, AWS IoT recibe datos e comunicación dun dispositivo que se redirixe a un recurso de AWS como un bucket de Amazon S3 (Simple Storage Service), unha táboa de DynamoDB ou calquera servizo de AWS.
