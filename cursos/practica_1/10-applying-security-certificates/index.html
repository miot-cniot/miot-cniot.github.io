    9. Aplicación de certificados de seguranza a unha cousa: visión xeral do proceso

    Nesta visión xeral do proceso aprenderás a aplicar certificados de seguranza á cousa que se creou nunha sección anterior e, a continuación, a actualizar a política de IoT para publicar e subscribirse a tópicos específicos.

    Declaracións de política

    Cada política ten varias declaracións de política, cada unha contendo accións, recursos e un efecto. A política que se vai usar nesta visión xeral do proceso ten dúas declaracións:

    • A primeira ten o efecto de Permitir. A acción é iot:Connect. O recurso contén unha variábel de política de cousas de AWS IoT que é substituída polo ClientID do dispositivo actual cando se avalía a política. Esta declaración de política permitirá que o dispositivo se conecte ao axente de mensaxes.

    • A segunda tamén ten o efecto de Permitir. A acción é iot:Publish. Esta cousa só pode publicar nos tópicos truck/freezer e truck/analyze. A información que provén deste dispositivo publicarase no tópico truck/freezer. Cando os datos se transforman, o tópico truck/analyze úsase para comprobar que os datos transformados teñen o formato agardado.

    JSON da política IoT

    JSON da política que se vai usar posteriormente nesta visión xeral do proceso. Cando se che indique terás que copiala e substituír os valores de YOUR_REGION co teu código de rexión de AWS, p.ex. us-east-1, e YOUR_ACCOUNT_NUMBER co teu número de conta de AWS.

    {
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "iot:Connect"
            ],
            "Resource": [
                "arn:aws:iot:YOUR_REGION:YOUR_ACCOUNT_NUMBER:client/${iot:ClientId}"
            ]
        },
        {
            "Effect": "Allow",
            "Action": [
                "iot:Publish"
            ],
            "Resource": [
                "arn:aws:iot:YOUR_REGION:YOUR_ACCOUNT_NUMBER:topic/truck/freezer",
                "arn:aws:iot:YOUR_REGION:YOUR_ACCOUNT_NUMBER:topic/truck/analyze"
            ]
        }
    ]
}

    Pasos do proceso

    Unha vez creada a cousa que representa o dispositivo, o seguinte paso é aplicar a seguranza configurando a política de AWS IoT. Os pasos a seguir son os seguintes:

    Configurar a política de AWS IoT

    1. No menú da esquerda na consola do servizo AWS IoT Core, escolle a opción: Xestionar (Gerenciar) -> Seguranza -> Políticas

      Xa se crearon un certificado e unha política para a cousa. A política base outorga á cousa dereitos para publicar e subscribirse a un conxunto de tópicos de exemplo. Vamos editar o documento da política para permitir que publique só nos tópicos que a cousa require para a proba de concepto.

      Políticas de AWS IoT mostrando a política truckSensor01.

    2. Preme no nome da política truckSensor01 para ver as súas propiedades, e deseguido preme no botón Editar versión activa e escolle o formato JSON.

    3. Elimina o contido actual do documento JSON da política.

    4. Copia e pega a política fornecida ao comezo desta sección, substituíndo os valores de YOUR_REGION polo teu código de rexión de AWS, p.ex. us-east-1, e YOUR_ACCOUNT_NUMBER polo teu número de conta de AWS.

      Edición do documento da política, vista JSON.

    Gardar a política como versión activa

    1. Debaixo do documento da política, no apartado Status da versión da política, marca a opción Definir a versión editada como a versión activa desa política.

    2. Preme no botón Gardar (Salvar) como nova versión para gardar a nova versión da política.

      Status da versión da política, definir a versión editada como versión activa.

    Copiar os certificados do dispositivo á instancia VSCode

    1. Localiza e descomprime o kit de conexión que baixaches previamente durante o proceso de creación da cousa. O nome por defecto era connect_device_package.zip.

    2. Sube a chave pública, a chave privada e o certificado (extensión cert.pem) ao cartafol certs na instancia VSCode. O cartafol certs xa debería conter o ficheiro AmazonRootCA1.pem, dos pasos de preparación.

      Ficheiros copiados á instancia VSCode.

    Co certificado e as chaves no seu lugar e a política bloqueada, o dispositivo está pronto para comezar a enviar e recibir datos.
