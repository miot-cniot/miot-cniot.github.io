    3. Compoñentes chave do AWS IoT Core

    Na proba de concepto, colocarase no camión un sensor de temperatura para medir e transmitir datos. Este tipo de sensor pode rastrexar a temperatura no conxelador, a tensión que chega ao conxelador e se a porta do conxelador está aberta.

    Traballando co AWS IoT Core

    O provisionamento dun sensor de temperatura e a seguranza dos datos e interaccións resultantes centrarase nos seguintes compoñentes do AWS IoT Core:

    • A pasarela de dispositivos (Device gateway) – O punto de entrada seguro para que os dispositivos IoT se conecten ao AWS IoT Core

    • O axente de mensaxes (Message broker) – Un axente de mensaxería que transmite de forma segura mensaxes cara e desde dispositivos e aplicacións IoT

    • Seguranza e identidade – Os requisitos para a autenticación e autorización de dispositivos e clientes

    • O rexistro de dispositivos (Device registry) – Unha base de datos de dispositivos e os seus atributos, que axuda a xestionar as cousas e organizar os recursos

    Vexamos cada un con máis detalle.

    A pasarela de dispositivos

    A pasarela de dispositivos é a responsábel da autenticación e autorización seguras entre o AWS IoT Core e os diversos dispositivos e aplicacións (tamén chamados clientes) conectados a el.

    Os dispositivos e clientes IoT necesitan comunicarse entre si e cos servizos de AWS IoT. Para este propósito úsase un protocolo chamado MQTT (Message Queuing and Telemetry Transport). MQTT é un protocolo de comunicación lixeiro de publicación/suscrición que se usa con dispositivos IoT.

    O axente de mensaxes

    O axente de mensaxes é un axente de mensaxería de publicación/suscrición baseado en MQTT de alto rendemento que transmite de forma segura mensaxes cara e desde os dispositivos e aplicacións IoT con baixa latencia.

    Co modelo de publicación/suscrición pode escollerse a información que se quere recoller. Os clientes envían datos publicando unha mensaxe nun tópico. Os clientes reciben mensaxes subscribíndose a un tópico. Os tópicos filtran e seleccionan mensaxes para a súa recepción. Ti defines o nome dos tópicos, cada un asociado a algún punto de datos para publicar/suscribir.

    Seguranza e identidade

    A seguranza é obrigatoria para os sistemas IoT e ten dous compoñentes principais:

    • Autenticación: Verifica a identidade dun usuario ou servizo

    • Autorización: Concede ou denega ao usuario ou servizo permisos para acceder a un recurso

    Hai dúas áreas onde se debe aplicar a seguranza nos sistemas IoT.

    1. Certificados e políticas de AWS IoT

    A primeira é dentro do propio fluxo de traballo de AWS IoT. Esta área de seguranza utiliza certificados e políticas de AWS IoT.

    Os dispositivos e cousas, e as aplicacións que se comunican con eles, deben autenticarse e deben ser autorizados para realizar as súas funcións (como enviar e recibir mensaxes). Os servidores que xestionan a comunicación e as mensaxes, como pasarelas e axentes, tamén deben ser autenticados e autorizados.

    AWS IoT admite tres tipos de identidades para a autenticación de dispositivos ou clientes. Este titorial centrarase nos certificados de cliente X.509 e os usuarios, grupos e roles de IAM. As identidades de Amazon Cognito non se tratarán aquí debido á súa alta complexidade.

    Un sensor de temperatura é quen de comunicarse cunha aplicación móbil a través dun axente de mensaxes. A autenticación faise usando certificados e a autorización usando políticas de AWS IoT, que están asociadas ao certificado.

    A autenticación e a autorización de dispositivos usando certificados e políticas trátanse con máis detalle en seccións posteriores deste titorial.

    2. IAM

    Na segunda categoría, os usuarios (tanto operadores humanos como actores software) precisan interaxir co sistema IoT ou entre si. Neste caso, a autenticación e a autorización fornécense mediante credenciais do servizo IAM (Identity and Access Management) ou, no caso da autenticación de terceiros, a través de AWS Cognito.

    Principio de privilexio mínimo

    Controlar quen pode facer que é obrigatorio nos sistemas IoT. O acceso só debe concederse a usuarios autorizados e deben ter os permisos limitados ás súas necesidades exactas. Por exemplo, un enxeñeiro de sistemas pode activar ou desactivar sensores, mentres que un operador só pode ler datos de sensores e recoller rexistros de datos.

    As políticas de seguranza para os usuarios pódense crear usando a consola de IAM. Os usuarios poden asumir roles, que confiren os permisos necesarios para tarefas específicas.

    Os roles e políticas de IAM trátanse en seccións posteriores deste titorial.

    O rexistro de dispositivos

    O rexistro de dispositivos é unha base de datos de dispositivos. Cataloga metadatos estáticos e atributos sobre os dispositivos, como números de serie, fabricante, versión de firmware, identificadores internos e capacidades do dispositivo.

    O uso do rexistro é opcional. Non é preciso crear unha cousa do AWS IoT no rexistro para conectar un dispositivo ao AWS IoT. O rexistro, con todo, mellora as capacidades de pesquisa mantendo unha listaxe de dispositivos e os seus atributos. O rexistro tamén pode publicar mensaxes de eventos cando se crean, actualizan ou eliminan cousas, tipos de cousas e grupos de cousas.

    Poden procurarse e xestionarse dispositivos usando a consola do AWS IoT, a API do AWS IoT ou a CLI (Command Line Interface) de AWS.
